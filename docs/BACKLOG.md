# StyleSense — Cross-Ticket Backlog

This file tracks open items surfaced during any ticket's Architect / Developer / QA / DevOps phase that are **out of scope for the ticket that found them** but need to be revisited later. A ticket's own worklog (`docs/worklog/SS-XXX.md`) stops being read once that ticket ships — this file is what stops a deferred decision from quietly disappearing into shipping velocity.

## Workflow (binding on all four pipeline agents)

Open items live in two tables — **Active** (relevant to the current/next sprint, scanned during ticket runs) and **Parked** (someday / blocked-on-external, *not* scanned during ticket runs). This split exists so the per-ticket hot path only reads the handful of rows that could actually matter now, instead of the whole backlog. Each row carries a **Tag** (`auth` / `schema` / `tokens` / `ci` / `ai` / `infra` / `test`) so a resurfacing check is a grep by tag, not a full read.

- **Logging (any phase, cheap append):** any phase that finds or defers an item that isn't a hard blocker for its own ticket appends a row — not just to the ticket's own worklog. Use the next sequential `BL-XXX` ID and a Tag. Put it in **Active** if a current/next-sprint ticket will plausibly hit it; otherwise **Parked**. Appending never requires re-reading the tables.
- **Resurfacing (once per ticket, Architect + orchestrator only):** the Architect phase (and the `/ticket` orchestrator, once, up front) scans the **Active** table — filtered by the tags relevant to the ticket about to run — for a row this ticket can resolve. Developer / QA / DevOps do **not** re-scan; they act only on rows explicitly handed to them in their prompt (plus the two scan-free actions below). **Parked is not scanned during ticket runs at all** — it's owned by `/audit` (see below).
- **Closing (scan-free):** when a phase resolves an item, it moves that row's `BL-XXX` from Active/Parked to **Resolved** with "Resolved by" (ticket/phase) and a one-line note. An agent always knows which `BL-XXX` it just resolved — no scan needed to close. Don't delete history — Resolved is the audit trail.
- **Parked reconciliation (`/audit` only):** the Auditor owns the **Parked** table — re-validating rows, promoting a row to **Active** when its sprint approaches, and resolving rows that are already stale. This keeps Parked from rotting without putting it on the per-phase hot path.
- This file is plain markdown edited by agents via their existing tools (Write/Edit for Architect/Developer, `Bash` heredoc-append for QA/DevOps/Auditor, which otherwise have no file-write tool) — never rewrite unrelated rows, only append/move.
- **Archiving:** once **Resolved** passes roughly 30 rows, move its oldest entries to `docs/BACKLOG_ARCHIVE.md` (create it on first archive). The archive is still the permanent audit trail — nothing in it gets deleted, only moved out of the live file.
