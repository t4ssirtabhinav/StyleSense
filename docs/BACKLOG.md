# StyleSense — Cross-Ticket Backlog

This file tracks open items surfaced during any ticket's Architect / Developer / QA / DevOps phase that are **out of scope for the ticket that found them** but need to be revisited later. A ticket's own worklog (`docs/worklog/SS-XXX.md`) stops being read once that ticket ships — this file is what stops a deferred decision from quietly disappearing into shipping velocity.

## Workflow (binding on all four pipeline agents)

- **Logging:** any phase that finds or defers an item that isn't a hard blocker for its own ticket, but might matter to a future ticket or needs a human/product decision, appends a row to the **Open** table below — not just to the ticket's own worklog. Use the next sequential `BL-XXX` ID.
- **Resurfacing:** before starting a ticket's Architect phase (or any phase, if relevant), check this file for **Open** rows whose domain overlaps the ticket about to run (colors/tokens, auth, schema, CI, etc.). If the ticket at hand can resolve one, do so and close it out (see below) instead of letting it ride further. If it's still not this ticket's job, leave it open — don't silently re-defer without a reason.
- **Closing:** when an item is resolved, move its row from **Open** to **Resolved**, filling in "Resolved by" (ticket/phase) and a one-line note on how. Don't delete history — the Resolved table is the audit trail.
- This file is plain markdown edited by agents via their existing tools (Write/Edit for Architect/Developer, `Bash` heredoc-append for QA/DevOps, which otherwise have no file-write tool) — never rewrite unrelated rows, only append/move.
