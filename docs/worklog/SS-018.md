**Verdict:** Design complete. `docs/tickets/SS-018-design.md` written.

**Key decisions:**
- REST command shape kept as `POST {url}/incr/{key}` (unchanged) + changed `POST {url}/expire/{key}/{seconds}` → `POST {url}/expire/{key}/{seconds}/NX`, called unconditionally (not gated on `count == 1`) after every `INCR`. `NX` ("set TTL only if none exists") makes this idempotent and self-healing across a crash between the two calls — eliminates the ticket's named race without needing full atomicity. Also added a JSON-body `"error"` key check (self-attack finding: Upstash is understood, trained-knowledge, to sometimes return HTTP 200 with a Redis-level error body) alongside `raise_for_status()` for both calls.

This is a deliberate, minimal exception to the raw ticket's Technical Notes ("no ... call-site changes should be needed") — resolved in the design doc in favor of AC 3's literal requirement, since the two cannot both be satisfied with zero changes outside `rate_limiter.py`.
