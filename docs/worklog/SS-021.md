### Architect — 2026-08-10

**Verdict: design complete** → `docs/tickets/SS-021-design.md`. Fresh pass; the stale 2026-07-28 branch's pass was not resumed, and both of its load-bearing conclusions were re-derived against today's schema.

**Key decisions**

1. **No Edge Function** (deviates from the raw ticket's stated shape, design §2). Every input to this score is data the caller already owns and RLS already scopes; an Edge Function would re-derive, over a network hop, a number the client can compute — while inheriting `BL-069`/`BL-042`/`BL-045` and a `verify_jwt = false` auth surface. A Postgres RPC was the close second and was rejected because it would put the formula in SQL, where this repo's only DB harness (`backend/tests/test_db_schema.py`) is skipped without `SUPABASE_DB_URL` — i.e. zero CI coverage on uncalibrated maths. Ships instead as a pure, unit-tested TS module over four narrow RLS-scoped reads, in a new `mobile/features/style-score/` domain. No migration, no `mobile/types/supabase.ts` regen.
2. **`activity` ships computed, not stubbed.** The prior pass's premise (`outfits` has no writer) is dead: migration `020_outfits_first_writer.sql` + `POST /outfit-suggestions/outcome` make it a real written table. Counts `2 × outfits + 1 × wears` per **IST** calendar month — wears included at half weight so "Mark Worn" users aren't scored 0 (minor, revertible deviation from the ticket's literal wording).
3. **AC #4 settled by precedent, not re-decided** — `BL-141`'s 2026-08-07 sign-off applied verbatim: text/deep-link fallback behind a `styleScoreCardExport.ts` seam mirroring SS-023's. Seam generalised by exactly one step (`ShareableCard` → `mobile/lib/share/shareableCard.types.ts`, SS-023's file re-exports it); SS-023's existing tests passing unmodified is the regression check.
4. `cost_efficiency` reads the `GENERATED cost_per_wear` column as **whole rupees** per `BL-075`. Dimensions with insufficient data score `null` and the total renormalises over the remaining weights — necessary because `purchase_price` is optional, so scoring it `0` would cap every real user at 80.
5. **`Risk: med`, revising the prior pass's `high`** — that label was correct for a design with an internet-reachable hand-rolled-auth endpoint; this design removes the surface rather than hardening it. `med` not `low` because of tier gating + a first production import of `react-native-svg`.

**Blockers before Developer** — two load-bearing sign-offs (design §10): **#1** the no-Edge-Function deviation, **#2** that premium sub-score gating is a UX gate rather than a security boundary (sets the precedent for all future premium-detail features). `med` puts this on the fast lane; the orchestrator should still pause on these two, then fast-lane the rest. Not blockers: `BL-141` (settled), `BL-075` (followed), `BL-022` (N/A — no swatches rendered).

**Backlog deltas** (orchestrator to apply; IDs from `BL-144` per the reservation notice) — **add to Active:** `BL-144` no server-authoritative score / `users.style_score` still has no writer (schema); `BL-145` scoring weights & targets are uncalibrated Architect defaults needing product sign-off (ai); `BL-146` `react-native-svg` first production import, Jest/web support unverified, fallback documented (infra); `BL-147` RN `Share` is a no-op under `react-native-web`, so SS-023's *and* this ticket's share buttons do nothing on the primary target (infra). **Unchanged:** `BL-141`, `BL-075`, `BL-022`, `BL-007` re-scanned and reaffirmed; `BL-049` gains one real call site (`premium_paywall_viewed`, `source: 'style_score'`). **No Active row resolved.**
