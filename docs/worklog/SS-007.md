# SS-007 — Granular Preferences Editor (Profile → Edit Preferences)

Branch: `feature/SS-007-preferences-editor`

## Architect

**Verdict:** Design complete — `docs/tickets/SS-007-design.md`.

**Key decisions:**
- New top-level route `mobile/app/edit-preferences.tsx` (not `app/(tabs)/profile/edit-preferences.tsx` as the raw ticket's Technical Notes suggested) — `profile.tsx` is a flat leaf file post-SS-005, not a directory; a top-level route follows CLAUDE.md's existing `outfit/[id].tsx`/`tryon/[outfitId].tsx` precedent instead of restructuring the tab. Self-guards session (same pattern as `(auth)/onboarding.tsx`), since it sits outside `(tabs)`'s Auth Guard.
- 5 independent sections (style keywords, wardrobe type, occasion priorities, budget range, colours), each with its own local component state (not `onboarding.store.ts` — wizard-scoped, reset on completion, wrong lifetime) and its own save mutation, satisfying "each section saves independently."
- New `patchStylePreferences` read-merge-write helper in `onboarding.service.ts` backing 5 new exported per-field update functions, matching the ticket's own named example (`updateOccasionPriorities`).
- Profile's "Edit Preferences" button repointed from `/onboarding` to `/edit-preferences`.

**Backlog deltas:**
- BL-025 → recommended Resolved (design closes the "no single-field edit" gap fully); finalize once Developer/QA confirm.
- BL-030 → updated, not resolved: Profile no longer reaches `/onboarding`'s "Welcome back!" framing at all, but the underlying bug (direct-URL entry to `/onboarding` for a completed user) is untouched — out of scope for this ticket.
- New BL-036 (Active, `schema`) logged: read-then-write race on `style_preferences` across two near-simultaneous section saves; not fixed here (would need an RPC-based atomic jsonb merge, disproportionate to this ticket's scope). Renumbered from this pass's original BL-033 by the orchestrator — SS-006 (concurrent, separate worktree) independently claimed BL-033/034/035 first.

**Blockers for Developer:** none hard. Two open Developer-judgment calls flagged in the design doc: (1) how to reuse `ColourSwatch` (export vs. duplicate — either acceptable), (2) none remaining re: checkout state — see Environment note below.

**Risk: low** — additive UI + partial-update writes to an already-write-permitted `users.style_preferences` column, no schema/RLS/secrets/payment surface, fully reversible.

**Environment note**: this Architect pass originally ran in a worktree mis-based on a stale `main` snapshot (predating this whole ticket pipeline). The orchestrator rebuilt the worktree fresh from `develop`'s current tip and copied this design doc/worklog across unchanged — the content above was already reconciled against the real current codebase (main checkout) during the original pass, so nothing here needed re-deriving. ## Developer

**Verdict:** Implemented strictly per the design doc. All 4 checks pass (tsc, biome, jest — see below); no design-doc deviations beyond the one explicitly left as Developer's judgment call.

**Files created:**
- `mobile/app/edit-preferences.tsx` — new top-level route, self-guards session (loading Card / `<Redirect href="/login">`, same pattern as `(auth)/onboarding.tsx`), fetches `useOnboardingProgressQuery` + one shared `useOnboardingTaxonomiesQuery`, gates the 5 sections' mount on `progressQuery.isLoading` settling (so each section's local `useState(initial...)` captures real data at first render instead of a useEffect syncing it in later — keeps the "no useEffect for derived state" rule intact), shows the "finish setting up" banner when `onboardingCompleted === false` (never a gate — sections stay editable underneath), plus an inline retry banner if the progress fetch itself errors.
- `mobile/features/onboarding/components/EditStyleKeywordsSection.tsx`, `EditWardrobeTypeSection.tsx`, `EditOccasionPrioritiesSection.tsx`, `EditBudgetRangeSection.tsx`, `EditFavouriteColoursSection.tsx` — each independently editable/saveable via its own local `useState` + its own mutation hook, own `isPending`/`isError` → "Try again" pattern, own loading/error/empty state for the 3 taxonomy-backed sections. Cap-hint copy and no-op-past-cap toggle logic for occasions (3)/colours (5) transcribed verbatim from `onboarding.store.ts`/Step3/Step4.

**Files modified:**
- `mobile/features/onboarding/onboarding.service.ts` — added `onboardingCompleted` to `OnboardingProgress`/`fetchOnboardingProgress`'s `.select()`; added private `patchStylePreferences` (read-merge-write, throws on either read or write error) plus 5 exported wrappers (`updateStyleKeywords`/`updateWardrobeType`/`updateOccasionPriorities`/`updateBudgetRange`/`updateFavouriteColours`), exact signatures per design doc #7.
- `mobile/features/onboarding/onboarding.queries.ts` — added 5 mutation hooks mirroring `useSaveStep1Mutation`'s shape, each invalidating `['onboarding', 'progress', userId]` on success.
- `mobile/features/onboarding/components/Step4BudgetColours.tsx` — exported `ColourSwatch`/`ColourSwatchProps` (previously private) for `EditFavouriteColoursSection.tsx` to reuse verbatim. **Judgment call (design doc's Open Questions #1): chose export over duplicate** — one source of truth for the 64px-square/corner-checkmark presentation rather than two copies that could drift; the only cost is `Step4BudgetColours.tsx`'s export surface widening slightly, which is low-risk since nothing else in that file changed.
- `mobile/app/(tabs)/profile.tsx` — `handleEditPreferences` now `router.push('/edit-preferences')` (was `/onboarding`).

**Tests added/updated** (Jest + RNTL, per design doc's Test plan): `onboarding.service.test.ts` (patchStylePreferences merge/null-current/read-error/write-error via `updateOccasionPriorities`, `onboardingCompleted` mapping true/false), `onboarding.queries.test.tsx` (5 new mutation hooks, invalidation assertions), `EditOccasionPrioritiesSection.test.tsx` / `EditFavouriteColoursSection.test.tsx` (pre-fill, cap no-op, hint-at-cap, deselect-then-select swap, Save-calls-mutation-with-current-selection, plus loading/error/retry), `EditStyleKeywordsSection.test.tsx` (no-cap multi-select, loading/error/empty), `EditWardrobeTypeSection.test.tsx` / `EditBudgetRangeSection.test.tsx` (single-select swap, Save disabled until a value is set), `app/edit-preferences.test.tsx` (5 sections pre-filled via mocked section stand-ins, session loading/redirect, banner shown/hidden by `onboardingCompleted`), and updated the existing `app/(tabs)/profile.test.tsx` assertion from `/onboarding` to `/edit-preferences`.
