**Design decisions worth flagging (full reasoning in the design doc):**

- **"Never fail a good write" made structural, not aspirational** (§3.4): resolve into locals then assign, so a failure leaves `NEW` untouched; `EXCEPTION WHEN OTHERS` → `RAISE WARNING` + `RETURN NEW`; no FK from `wardrobe_items.pattern`/`.fabric` to the registries, ever (asserted by test #27). Test #29 proves the guard empirically by renaming the capture table inside a rolled-back transaction and asserting the item insert still succeeds — not by inspection.
- **Two triggers, not one** (`BEFORE INSERT` + `BEFORE UPDATE … WHEN (NEW.x IS DISTINCT FROM OLD.x)`), diverging from `008`'s single-trigger shape. This keeps the wear-stats `UPDATE` out of plpgsql entirely and stops capture `occurrences` inflating on every wear. Tests #22/#23.
- **Resolvers are pure; only the trigger logs** — diverges from `garment_normalize_one` (014), which logs from inside itself with NULL context. Lets the trigger log real `TG_TABLE_NAME`/`user_id`, and lets the backfill call the resolver twice (WHERE + SET) without double-counting.
- **`is_active` is excluded from resolution** — filtering on it would reclassify existing item values as "unknown" the moment a row is deactivated, i.e. the exact orphaning the ticket's edge case 5 forbids. Commented loudly in the migration and asserted by test #30.
- **Fabric attributes: decided, not deferred** (§3.6, the ticket's explicit open question) — `weight`/`breathability`/`season_affinity` land now, seeded for all 11 rows. They're inert this ticket (nothing reads `fabrics.*`; only `.key` is consulted), and authoring 11 rows is cheapest the moment the rows are first written — SS-034's own BL-109 reasoning applied to the direct analogue. Values flagged as Architect judgment (`BL-125`), with a clean fallback in §9 if the reviewer prefers unseeded or absent columns.
- **One shared `attribute_unknown_tags`** (discriminated by `attribute`) rather than two tables — satisfies the AC's literal "shared" wording, avoids colliding with SS-034's `garment_unknown_types`, and leaves BL-064's colour half a CHECK widen rather than a third table.
- **Seed transcribed verbatim** from BL-064's recorded SS-012 prompt vocabulary (11 patterns, 11 fabrics, order preserved). No vocabulary invented. Known imperfections (`chikankari`/`khadi` are techniques not fibres; `printed` ⊃ `block_print`) flagged in §7/§9 rather than silently "improved".
- **No application-layer normaliser** — a deliberate deviation from SS-025's BL-078 posture and SS-035's boundary-7 choice, to keep a `Risk: high` diff's blast radius to the trigger alone. Cost is that a user's typed "Raw Silk" reads back `silk`; follow-up logged as `BL-127`.
