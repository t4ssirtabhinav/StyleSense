## Architect — 2026-07-28

**Verdict:** Design complete — `docs/tickets/SS-025-design.md`. **Risk: high (confirmed, full lane — every human gate preserved).** Creates and alters schema on a live project, drops a type and a table, adds RLS policies and this repo's first `SECURITY DEFINER` functions, backfills user preference data, and changes occasion handling across seven shipped tickets. Every one is a §C2 one-way door.

**Key decisions:**

- **Three migrations, not one** — `007` expand (registry + aliases + RLS + seed + normalisation functions), `008` migrate (four columns → `TEXT`/`TEXT[]`, normalisation triggers, GIN-survival guard), `009` contract (alias-backfill of `users.style_preferences.occasions_priority`, `DROP TYPE occasion_type`, `DROP TABLE occasion_types`). Each carries its own rollback block. Forward-only; `001_initial.sql` untouched.
- **`badge_color` is a design-token key, not a hex** — `NOT NULL` + `CHECK` against SS-008's four occasion tokens, which *are* `Badge`'s existing `OccasionKey` union. NativeWind classes resolve at build time and CLAUDE.md forbids inline styles, so a free DB hex is unrenderable. Consequence: `Badge.tsx`/`tokens.ts`/`tailwind.config.js` need **no changes**, and every occasion is coloured by construction.
- **DB-level normalisation trigger + `occasion_unknown_tags` capture table** as the backstop under the application-layer normalisers. This is what lets the three write paths that don't exist yet (outfits, social posts, suggestion sessions) be honestly called covered rather than deferred.
- **Hierarchy does the surface-scoping** — onboarding Step 3 and home pills read `parent_key IS NULL`; new specific occasions seed with a parent, so inserting `ganesh_chaturthi` reaches wardrobe tagging, filters and the Gemini prompt without flooding the onboarding wizard. No column invented beyond the approved plan.
- **Sharpest regression risk found by grep, not in the ticket:** Review/Edit currently render chips from `OCCASION_TYPES.map`, so any tag not in that list is invisible and gets dropped on save. Fixed with a union rule (active registry ∪ tags already on the item) — this is what makes the deactivated-occasion and unknown-AI-slug edge cases actually hold.
- **Two alias rows are load-bearing data migration, not conveniences:** `wedding → wedding_guest`, `date → date_night` — the shipped onboarding table and home pills use the old keys, and live user preference data does too.
- Blast radius corrected `[VERIFIED 2026-07-28, grep]`: 3 migrations (not 1), 5 backend source + 3 new, 5 backend test files (not 6) + 2 new, 32 mobile source files reference occasions (19 need edits, 13 don't) + 31 test files.

**Backlog deltas:**
