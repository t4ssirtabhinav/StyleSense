Design maps the raw ticket's E0–E2 table onto a new `ENGINE_V2_EFFORT_TIER_SPEC` (`app_config_specs.py`) and a pure `resolve_effort_tier()` + async `resolve_effort_tier_for_request()` orchestrator (new `engine_v2_effort_dial.py`), reusing SS-028's `RoutingMixMonitor`/SS-029's `CostBudgetGate` rather than duplicating health/budget logic.

**Two real gaps found and designed around, not silently assumed away:**
1. SS-029's `CostBudgetGate` had no read-only status method (only mutating `reserve()`) — added `IRateLimiter.peek()` (new non-mutating GET) + `CostBudgetGate.budget_status()`, both purely additive, never touching the existing atomic-`INCRBY` enforcement path.
2. SS-028's `RoutingMixMonitor` tracked per-provider failure state privately but exposed no public read — added `provider_is_down()` as a thin accessor over that same already-tracked state (no new detection/alerting).

Both required touching files beyond the ticket's stated two-file list (`adapters/interfaces.py`, `adapters/upstash_rate_limiter.py`, `services/cost_budget_gate.py`, `services/routing_mix_monitor.py`, plus their existing fakes in two test files) — flagged explicitly in the design doc's "Files to create/modify" and "Open questions" rather than left implicit.

**Also found: two of the ticket's dial parameters don't behave as its own AC assumes, given SS-038's actual shipped code** — `colour_mode` has no real toggle at all (SS-038 unified to pairwise-only, no "star" mode survives), and `search_pool_size`/`top_k_bases` is a complete no-op at all three tiers' magnitudes (all ≥ SS-038's private, unexposed 50-base expansion cap). Design keeps both wired through as literal, harmless, forward-compatible pass-throughs but does **not** claim they produce observable per-tier differences — AC #3's integration proof is satisfied instead via `mmr_lambda`/`max_exploration`, which do. Full traces in the design doc's Open Questions #3/#4.
