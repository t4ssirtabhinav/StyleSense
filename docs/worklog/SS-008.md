## Architect

Design doc: `docs/tickets/SS-008-design.md`.

Read the ticket, CLAUDE.md, and verified the actual `mobile/` codebase state before designing (not assumed): `mobile/components/` doesn't exist yet (greenfield build); `mobile/tailwind.config.js` already has the flat `brand/dark/peacock/emerald/rose` colour keys matching the ticket's token hex values 1:1, confirming the ticket's own reconciliation note; `mobile/app/_layout.tsx` is a bare `<Stack>` with no font loading, no `GestureHandlerRootView`, no `BottomSheetModalProvider`; `mobile/jest.config.js` already anticipates `components/ui/**` coverage; `@gorhom/bottom-sheet`, `react-native-reanimated` v4, `react-native-gesture-handler`, and `react-native-svg` are already installed (their peer-dependency chain is satisfied), but **`expo-font`, all five `@expo-google-fonts/*` packages, and `@expo/vector-icons` are completely absent** from both `package.json` and `node_modules` (confirmed via direct glob, zero matches) — this is a same-ticket blocker the Developer must resolve via `npx expo install` before any component compiles.

**Key design decisions made:**
1. **`mobile/app/index.tsx` migration: in scope, done now** (not deferred to SS-005) — trivial 13-line file, good smoke test for the new components, but flagged to the Developer as disposable since SS-005 will likely replace its contents entirely.
2. **Tailwind colour-key flattening**: `tokens.ts` keeps the ticket's exact nested structure (`colors.bg.primary`, etc.) verbatim, but `tailwind.config.js`'s theme layer uses flattened, renamed keys (`surfacePrimary`, `textPrimary`, `occasionWedding`, etc.) to avoid Tailwind's `bg-bg-primary`/`text-text-primary` class-name stutter. Same hex values, presentation-layer naming only.
3. **`Input` component API fully fixed**, since SS-003 depends on it most: 4 variants (`text/phone/search/otp`), with explicit documentation of what SS-008 provides (visual chrome, box-rendering, shake-on-error, `onComplete` callback) vs. what SS-003 must build itself (validation logic, the actual Supabase OTP verify call, resend-cooldown timer, SMS auto-read — SS-008 has zero SMS code).
4. **Button's "4 variants" (ticket's wording) reconciled** to 3 colour variants (`primary/secondary/ghost`) + a `disabled` boolean state that composes with any of them, since there's no distinct 4th colour design implied elsewhere in the ticket — flagged explicitly as an interpretation call, not silently decided.
5. **Font loading does not gate `_layout.tsx` render on `fontsLoaded`** — renders immediately, logs `fontError` to Sentry if present, and relies on React Native's built-in fallback-to-system-font behaviour when a custom `fontFamily` isn't registered. This satisfies the ticket's edge case ("not blank screen") without requiring a new `expo-splash-screen` dependency.
6. **Skeleton shimmer**: opacity-pulse via the already-installed `react-native-reanimated`, not a gradient-sweep (which would need `expo-linear-gradient`, not installed) — flagged the gradient approach as a possible future enhancement, not required for this ticket's AC.

**Gaps found:**
1. **Missing dependencies** (`expo-font`, 5× `@expo-google-fonts/*`, `@expo/vector-icons`) — same-ticket blocker, not downstream; must be installed before component code compiles.
2. **No semantic error/danger colour exists in the given token set** — `accent.rose` is explicitly scoped to the beauty/makeup module, not general form validation. Needs a Product/design decision on an error colour before `Input`'s error state is styled; deliberately not invented here.
3. **Occasion colour coverage gap**: the ticket defines only 4 occasion colours (`wedding/office/festival/casual`), but SS-002's `occasion_type` enum has 12 values, and SS-004 (9 options)/SS-005 (6 pills, including "Date"/"Party") will need colours this ticket doesn't provide. Flagged for Product to extend before those tickets' Architect passes, not silently resolved with invented hex values.
4. **`GestureHandlerRootView`/`BottomSheetModalProvider` don't exist anywhere yet** — must be added to `_layout.tsx` in this ticket, since any `@gorhom/bottom-sheet` usage will otherwise fail at runtime.
5. **`mobile/app/dev-ui-kit.tsx`** (the required Storybook-style test screen) will ship in production bundles since Expo Router has no dev-only route exclusion — flagged as a minor open question, not currently a blocker.
6. **BottomSheet Android device-matrix testing** (Samsung One UI, Xiaomi MIUI, stock Android per the ticket's edge case) cannot be performed by any agent in this pipeline — flagged as a manual QA step for the user, separate from the automated test suite.

**Blocker for Developer phase:** #1 (missing dependencies) must be resolved first — nothing in `components/ui/` will type-check or run without `expo-font`/`@expo-google-fonts/*`/`@expo/vector-icons` installed. #2 and #3 (error colour, occasion colour coverage) don't block building the components themselves (can proceed with a placeholder/neutral fallback) but should be resolved before those states ship to users.

**Verdict:** Architect complete. Not yet reviewed by a human — per the ticket skill, a human should read `docs/tickets/SS-008-design.md` before the Developer phase starts.

**Gaps found beyond the design doc (not flagged by the Architect, discovered by actually running the code):**

## Manual Verification (user, in browser)

User ran `npx expo start --web`, hit a separate connectivity issue (phone on same WiFi couldn't reach the dev server/QR code — logged as **BL-013** in `docs/BACKLOG.md`, parked; browser check at `/dev-ui-kit` was sufficient for this ticket), then opened `http://localhost:8081/dev-ui-kit` in-browser per QA's instruction.

**Bug found: AC 6 (OTP boxes) — boxes rendered vertically stacked instead of in a horizontal row.**

Root cause (found and fixed directly, not via a subagent phase): NativeWind v4's `className` interop only auto-registers on core React Native primitives — it does **not** cover `Animated.View` from `react-native-reanimated` (confirmed via grep: no `cssInterop`/`remapProps` registration exists anywhere in the codebase to bridge that gap). Two components had `className` on a reanimated `Animated.View`, silently ignored:

- **`Input.tsx`'s `OtpInput`**: `<Animated.View className="flex-row" style={shakeStyle}>` — the `flex-row` class was dropped, so the row fell back to RN's default `flexDirection: 'column'`, exactly matching the reported bug. Fixed by setting `flexDirection: 'row'` inside the `useAnimatedStyle` object instead of via className.
- **`Skeleton.tsx`**: `<Animated.View className="bg-surfaceSecondary rounded-lg" .../>` — same silent no-op, meaning the shimmer would have rendered with no background color and square corners (this was one of the AC 7 items QA had already flagged as unverifiable — confirmed it would have failed visual inspection too). Fixed by reading `colors.bg.secondary`/`radii[variant]` from `tokens.ts` directly into the inline `style` array alongside the animated opacity style.

Both fixes verified: `npx tsc --noEmit` clean, `npx jest` still 14/14 suites and 69/69 tests passing (no test depended on the removed className strings), `npx biome check .` clean. User re-checked `/dev-ui-kit` after the fix and confirmed both the OTP row and the Skeleton shimmer now render correctly.

**Remaining visual ACs (BottomSheet snap/drag, typography, colour contrast, Badge truncation UX) confirmed acceptable by the user** — no further issues reported.

**Updated verdict: PASS.** All ACs met (BL-007/BL-008 remain intentionally parked per user instruction; BL-013 remains open, unrelated to this ticket's own AC). Ready for DevOps.
