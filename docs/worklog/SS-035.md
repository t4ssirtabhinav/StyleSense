**Key decisions**

- Constraint widens to `UNIQUE NULLS NOT DISTINCT (item_id, worn_on, occasion_key)` — the modifier *is* `BL-071`'s preservation mechanism; without it unlimited `NULL`-occasion duplicates re-open the exact bug SS-015 fixed, silently.
- **No FK from `occasion_key` to `occasions(key)`** — deviates from the raw ticket's "`ON DELETE RESTRICT`" edge case, which is flatly incompatible with its own AC #1 (unknown slugs must never fail the write) and with every other occasion column in the schema. No-FK delivers the intended outcome (history not re-writable) more strongly.
- `outfit_id` uses `006`'s composite-FK convention with **`ON DELETE SET NULL (outfit_id)`** — the column list is mandatory, not stylistic: a bare `SET NULL` would try to null the `NOT NULL user_id` and make outfit deletion *fail*, i.e. the opposite of AC #2.
- Migration is self-verifying: a version gate (first statement) and a temp-table before/after guard that `RAISE`s if any pre-existing `wear_count`/`last_worn_at`/`cost_per_wear` moved (AC #5).

**Blockers the user/Developer must resolve before Developer starts**

1. **Live PostgreSQL version is UNVERIFIED and gates the whole DDL** (Q1). `config.toml:42` says 17 but that is the *local* stack; the remote was permission-denied on 2026-07-30 and this pass had no Bash/psql/dashboard access. Developer must run `SELECT current_setting('server_version_num')` against `mefpfykuinasgkpfhmzk` **before writing DDL**. `<15` ⇒ design §3.8 fallback, which makes the RPC write path mandatory — a scope change needing operator sign-off.
2. **Product decision on `wear_count` semantics** (Q2): a two-occasion day now counts **2**, halving that day's `cost_per_wear` contribution. Design keeps `COUNT(*)`; the alternative is one line. `BL-075`'s money class — confirm or overrule at this gate.
3. Q3 (occasion optional ⇒ signal may stay sparse), Q4 (`mobile/types/supabase.ts` regen collides with sibling worktrees, and unlike SS-033 the mobile code *needs* it to typecheck) are flagged but not blocking.

**Backlog deltas** — recorded in design §10 for the operator to apply to the main checkout (no `Edit` tool here; `BACKLOG.md` is shared state). `BL-078` **stays Active**, boundary 7 added and covered by **both** a new dedicated `SECURITY DEFINER` trigger and app-layer normalisation (first boundary to ship with both). `BL-071` honoured, not regressed — and its **Active copy at `BACKLOG.md:51` is a stale duplicate of the Resolved entry at `:139`; recommend deleting it**. `BL-004` note-only: risk does **not** extend — the new columns are user-authored facts, not derived caches.
