**Migration approach: (a) alias rows — chosen over the ticket's stated preference for (b) enum→TEXT FK.** Reasoning recorded in full in the design doc. Short version: `occasion_type`'s values mapped 1:1 onto same-granularity registry keys; garment values do not (`footwear_ethnic` is a formality bucket spanning jutti/kolhapuri/mojari; `ethnic_lehenga` is ambiguous between the skirt and the set), so (b) would require inventing per-item garment knowledge the column doesn't contain — a lossy, irreversible backfill. (b) also breaks `CATEGORY_SLOT[item.category]`'s bare subscript on a live scoring path, and the vision adapter can only emit the 21 coarse values anyway, so it would leave the column in a mixed vocabulary. (a) needs **zero backend code change** — `garment_registry_adapter.py` already resolves aliases from its cached snapshot — and is additive/reversible. CONTRACT (dropping the enum) is explicitly out of scope → `BL-192`.

#### Self-Attack Sweep (Schema Ticket Class)

1. **Idempotency** — Re-running the migration at SQL level would fail with unique constraint violations (INSERT on already-seeded rows). This is expected for Postgres migrations; idempotency is enforced at the framework level (Supabase migration tracking), not SQL level. Acceptable.

2. **Unknown enum value** — T1 fixture test (CI-enforced) iterates all 21 WardrobeCategory members and asserts an alias exists for each. A future enum value added without an alias fails the test loudly rather than silently degrading.

3. **register_coherence side effects** — Design edge case 6 correctly identifies this as a live behavior change: mixed-register pairings (e.g. western top + ethnic bottom) now actively score 0.5 instead of 1.0, down-ranking outfits that scored equally before. V3 verification script prints before/after portfolio ordering so the change is observed, not assumed. Live behavior change is intended and verified.

4. **volume_class merge safety** — Migration uses JSONB merge (`||`), so rows with existing `styling_rules` (e.g. saree children with `{"length_yards":6}`) preserve their keys: `'{"length_yards":6}' || '{"volume_class":"relaxed"}'` = `'{"length_yards":6,"volume_class":"relaxed"}'`. Safe and tested (T4 guards every resolved row has volume_class populated).
