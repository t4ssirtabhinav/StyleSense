**Key decisions:**
- Targeted the *shipped* Wave 2 code (`EngineV2.generate_portfolio`, `engine_v2_effort_dial.py`) per the orchestrator's briefing, not SS-027 v0 — confirmed no residual `styling_rules_engine.generate_candidates`/`score_candidate` calls anywhere in scope.
- Discovered `IStylingProvider` as shipped (SS-006/SS-028) has no method that accepts pre-assembled candidates and no `item_id`-bearing return shape — it cannot satisfy the "no hallucinated item IDs" AC as-is. Added a new port capability (`narrate_candidates`, additive ABC method, same class of change SS-039 made to `IRateLimiter.peek()`), implemented on all 3 adapters + `StylingRouter`. This is real new scope beyond "pure assembly," flagged explicitly (Open Question #4) rather than silently absorbed into the existing 20h estimate.
- Designed the combination-signature cache (raw ticket's own named one-way door) as a **narration-only** cache: Engine v2's own per-user personalisation (novelty/wear-recency) always runs fresh per request and is never cached; only the LLM's prose is shared, keyed on a salted HMAC of a coarsened (category, colour-family, formality-band) shape with no `user_id`/item-id column at all — resolves the "personalisation must not leak" vs. "novelty personalises the candidate set itself" tension. New table + migration `019`, RLS default-deny (service_role only, mirrors `IAppConfigRepository`).
- Flagged (Open Question #1) that satisfying the literal "<200ms cache hit / <4s cold call" AC requires awaiting the pipeline synchronously inside the request handler, not `BackgroundTasks` fire-and-forget — a direct textual conflict with CLAUDE.md's "never call AI APIs synchronously" line. Recommended reading (never block the event loop with sync I/O, which this design never does) but flagged for explicit sign-off rather than defaulted, since it's the highest-traffic endpoint in the product.
- Closed `BL-052` for the new `/portfolio` route only (migrates to `dependencies/auth.py::get_current_user_id`); the pre-existing `/generate` stub is deliberately untouched (no real caller, out of scope).
- Additive-only signature widening on `EngineV2.generate_portfolio` (`search_pool_size`, `mmr_lambda`, `effort_tier`, `tier`, `request_id` — all new optional kwargs, defaults match current hardcoded behaviour) — needed because the shipped signature doesn't actually forward two of SS-039's four dial fields despite `styling_rules_defaults.py`'s own comment saying it should.
- Widened `OccasionRegistrySnapshot` (additive `dict` fields: `kinds`/`formalities`/`styling_rules`) — nothing shipped today can turn an occasion key into the `kind`/`formality`/`styling_rules` triple `OccasionStylingInput` requires.

### AC renegotiation — orchestrator decision (2026-08-07)

Presented the latency finding to the user before sending to QA rather than let it surface as a silent AC failure in the QA table. **User decision: renegotiate the AC**, same class as `BL-058`/`BL-067`/`BL-100`. Applied:
- `docs/tickets/raw/SS-020.md`'s latency AC rewritten: no flat "<4s, slowest model" ceiling. Instead, a policy-timeout-then-degrade framing — a model finishing inside `StylingRouter`'s `attempt_timeout_seconds` (6s default) returns a real narration under that ceiling; Claude Sonnet 5 (measured 16.2-16.7s) is *expected* to hit the timeout and degrade to rule-based reasoning, which is the tested "never a hard error" path, not a defect.
- Deliberately did **not** bump `attempt_timeout_seconds`/`total_deadline_seconds` — that policy is shared with `suggest_outfits` (SS-028's own already-`PASS`-verdict feature), so widening it is a separate routing-table decision belonging to a future SS-028 pass, not folded silently into this renegotiation.
- `BL-139` updated to record the renegotiation and leave "should Sonnet-class models even be routed to this synchronous call" open for that future pass.

**QA should verify the AC as renegotiated** (`docs/tickets/raw/SS-020.md`'s current wording), not the original "<4s" text.
