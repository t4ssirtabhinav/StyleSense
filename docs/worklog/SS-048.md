**Key design decisions:**
- `todays_picks`/`newest_pieces` share a **single** `EngineV2.generate_portfolio` call per user per recompute (widened `portfolio_size_range=(15,20)`, an existing kwarg), sliced two ways — not two engine calls, satisfying the AC's "no second scoring implementation" literally and efficiently.
- `never_tried_pairs`/`not_yet_worn` are pure Python query-layer functions (`suggestion_rails_query.py`) with zero `engine_v2*` imports, proven by a dedicated test — matches this codebase's existing "pure stage function" convention rather than the competitive doc's literal `NOT EXISTS` SQL framing (also sidesteps a real gap: no dedicated "ethnic bottom" `wardrobe_category` value exists, so a category-name SQL join can't be written correctly today).
- `outfits.item_ids` alone covers "never co-occurred in a saved outfit **or an accepted suggestion**" — confirmed via `outfit_repository.py`/the `/outcome` router that every `saved`/`worn`/`shared` outcome already writes an `outfits` row; no second table join needed.
- Debounce: `app_config`-driven `RAIL_PRECOMPUTE_DEBOUNCE_SPEC`, 600s default (transcribed from `08-CHEAP-SUGGESTION-ENGINE.md` §5.2's own "~10 min" table, not invented). No real background job/cron — none exists to run one against (`BL-037`). `GET /suggestion-rails` is a **pure read**, no side effects; only wardrobe writes (`/tag`, `DELETE /items/{id}`, `/outcome` saved/worn) and the explicit `POST /suggestion-rails/refresh` trigger recompute.
- `BL-134` (two non-interchangeable `outfit_fingerprint` impls): not resolved, but this ticket's rail payloads use `engine_v2_portfolio.compute_outfit_fingerprint` exclusively (matching `EngineV2`/`OutfitPortfolioService`), avoiding a third divergent caller.
- Two shared modules (`occasion_resolution.py`, `wardrobe_fetch.py`) extracted from `OutfitPortfolioService`'s private methods so the rail job reuses the live endpoint's exact occasion-resolution/wardrobe-fetch logic rather than a parallel copy — flagged as the riskiest refactor (existing SS-020/22/23 test suite is the regression guard).

**Backlog:** appended `BL-197` (rail precompute skips weather, deliberate) and `BL-198` (no bootstrap path for existing users' rails — directly relevant to `SS-049`) to Active. Added a re-scan note to `BL-134` (not moved). Updated the BACKLOG.md ID-reservation notice to top out at `BL-198`.
