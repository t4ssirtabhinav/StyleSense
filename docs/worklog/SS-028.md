**Implementation decisions not fully mechanised by the design text:**
1. **Provider→model map for cross-provider failover.** §4.1's `failover` map only names provider IDs (`{"gemini": ["claude"]}`), never a model — but a failover hop to a different provider needs *some* model ID. `StylingRouter._provider_model_map()` derives it by scanning the routing table's own `default` + `rules` for whichever model each provider is already routed to elsewhere in the same table (in the shipped table: gemini→`gemini-2.5-flash-lite`, claude→`claude-sonnet-5`). Documented in the router's own docstring; a provider named only in `failover` with no route anywhere in the table degrades gracefully via the existing N4 "unknown provider" path rather than `KeyError`.
2. **`GeminiStylingAdapter`'s in-tier fallback-model retry** (§4.1's "retry-hop detail inside the Gemini adapter's call logic") is implemented as: on ANY classified failure of the primary model, retry once against `fallback_model` before raising to the router; whichever attempt succeeds is what `StylingCallMetrics.model` reports. Invisible to the router's per-attempt log line, exactly as the design specifies.
3. **N8 (missing API key) required an adapter-level fix during test-writing**, not just a design read: `_get_client()`'s `os.environ[...]` `KeyError` was originally outside both adapters' `try` blocks, which would have let it propagate raw into `StylingRouter`'s ladder (uncaught by any `Provider*Error` except-clause) and up into the `BackgroundTasks` callback — exactly the `BL-096` crash class the design explicitly forbids. Fixed in both adapters: client construction now happens inside its own `try/except KeyError → ProviderPermanentError`. Caught by `test_missing_api_key_raises_provider_permanent_error_not_key_error` in both adapter test files, and implicitly exercised by every `test_outfit_suggestions_router.py` test that doesn't override `get_styling_provider` (no `GEMINI_API_KEY`/`ANTHROPIC_API_KEY` in `conftest.py`'s baseline env) — those now correctly degrade to `MockStylingAdapter` rather than raising.

**DI wiring:** `get_app_config_snapshot` (new `dependencies/app_config.py`, shared by both routers) is FastAPI's per-request-cached dependency backing every `Depends()` helper in `outfit_suggestions.py` — `app_config_service.snapshot()` fires at most once per request by construction (N2), asserted directly in `test_styling_router.py` via a monkeypatched call-counting `resolve_route`. `ProviderQuotaTracker`/`RoutingMixMonitor`/`StylingProviderRegistry` are process-wide singletons (mirrors `routers/wardrobe.py`'s `_gemini_rate_limiter`/`_occasion_normalizer` precedent) with new `set_ceilings()`/`configure()` setters applied from the live config snapshot every request — a fresh instance per request would silently make the in-process sliding windows/rolling sample no-ops. `routers/wardrobe.py::get_gemini_rate_limiter()` is now `async`, reads `GEMINI_QUOTA_CEILING_SPEC` off the same shared snapshot dependency, and applies it via the new `GeminiRateLimiter.set_max_requests()` — constructor default stays `15` so `test_app_config_service.py`'s existing drift-guard test is unaffected.
