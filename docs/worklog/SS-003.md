**Key design decisions:**
1. **Route architecture**: `/` maps to `app/(tabs)/index.tsx` (moved from the current top-level `app/index.tsx`, which must be deleted as part of the move — Expo Router would otherwise have two files resolving to the same path). `app/(tabs)/_layout.tsx` is the Auth Guard (loading state → `Card`/`Text`, no session → `<Redirect href="/login">`, valid session → `<Slot />`, deliberately not `<Tabs>` yet since SS-005 hasn't built tab-bar UI — flagged for SS-005's Architect to reconcile). `app/(auth)/login.tsx`, `verify-otp.tsx`, and a disposable `onboarding.tsx` placeholder (same pattern SS-008 used for `app/index.tsx`) round out the auth routes.
2. **Domain split per CLAUDE.md's convention**: `features/auth/auth.service.ts` (raw `supabase.auth.signInWithOtp`/`verifyOtp`/profile-exists calls + pure `validateIndianMobile`), `auth.queries.ts` (React Query mutations/query — the only place these are called from components), `auth.store.ts` (Zustand, session only — everything else, phone-in-progress/OTP value/resend countdown, is local screen state since nothing else consumes it), `auth.types.ts`. Session listener wiring (`supabase.auth.onAuthStateChange`/`getSession`) lives in a new `hooks/useAuth.ts` (CLAUDE.md's folder structure explicitly names `useAuth` as a `hooks/` example), called once from root `_layout.tsx`.
3. **`Input`'s existing mechanics reused, not reimplemented**: confirmed by reading `Input.tsx` directly that paste-fill, auto-submit-on-6th-digit (`onComplete`), and shake-on-error (falsy→truthy `error` transition) are already built by SS-008 — SS-003 only sets/clears the `error` string and wires `onComplete`.
4. **First-login vs. returning-user heuristic**: since `public.users` has no auto-provisioning trigger or `onboarding_completed` flag (verified directly against the SQL), designed around row-existence (`checkUserProfileExists`) as the signal, explicitly flagging that this only half-closes the AC until SS-004's onboarding flow actually creates the row — logged as **BL-018**.
5. **SMS auto-read scoped as a documented no-op**: no `expo-sms-retriever`-equivalent package exists in the repo, none is chosen by this design doc, and even a correctly chosen package couldn't be device-verified today (BL-013). `hooks/useSmsAutoRead.ts` is specified as a stub that's a guaranteed no-op outside Android, wired unconditionally so a real implementation later is additive. Logged as **BL-019**.
6. **Wrong-vs-expired OTP cannot be reliably distinguished** — Supabase surfaces the same generic error message for both; designed a single generic error copy rather than inventing a client-side heuristic to fake a distinction the API doesn't expose.
7. **Resend cooldown (30s) is local `useState`+`setInterval` in `verify-otp.tsx`, not global store state** — a legitimate timer side effect (not "derived state" in the sense of CLAUDE.md's anti-pattern rule), and nothing outside that one screen needs it.
8. **Country code picker scoped to India-only for MVP** (`features/auth/components/CountryCodePicker.tsx`, wrapping `components/ui`'s existing `AppBottomSheet`) — no other country is specified anywhere in the ticket/schema/backlog, so no country list is invented.

**Gaps found:**
1. **BL-001 reconfirmed** as this ticket's central blocker for end-to-end testing — design targets Supabase's Phone Auth abstraction generically; only the actual OTP-delivery network call and SMS auto-read AC are unverifiable until MSG91/Twilio is configured. Everything else (validation, navigation, session persistence/propagation, mocked Supabase calls) can be built and unit-tested now.
2. **New gap (BL-018)**: no `public.users` auto-provisioning trigger / `onboarding_completed` flag — affects the onboarding-vs-home routing AC, needs a decision that spans SS-002 (infra) or SS-004 (application-level insert), not resolvable within SS-003 alone.
3. **New gap (BL-019)**: no SMS auto-read library chosen; compounds with BL-013 (no real Android device reachable for testing even once a library is chosen).
4. **BL-007 reused, not resolved** — `Input`'s existing `errorPlaceholder` colour constant is consumed as-is for both screens' error states, per the design doc's explicit instruction not to invent a second error-colour source.

BL-001 blocks only the final end-to-end verification (real OTP delivery, real SMS auto-read), which should be recorded as "built against mocks, not verified end-to-end" in the Developer/QA worklog sections, mirroring how SS-002 framed the same gap.

## BL-001 refinement (user discussion, pre-Developer)

User asked how to navigate/authenticate/test this feature without MSG91 configured. Researched (WebSearch, verified against Supabase docs) and found two corrections to the ticket's original assumption, both backfilled into BL-001 in `docs/BACKLOG.md`:

1. **MSG91 is not a native Supabase Auth SMS provider** (natively supported: Twilio, Twilio Verify, MessageBird, Vonage, TextLocal) — using it requires a custom "Send SMS Hook" Edge Function, not a dashboard toggle. More implementation work than the ticket assumed.
2. **Twilio does not bypass India's DLT requirement** — DLT registration is tied to the destination (Indian carriers), not the sending vendor, so Twilio trial credit doesn't unblock real SMS to India any faster than MSG91 would.

**Decision: unblock the Developer phase using Supabase's built-in Auth "Test OTP" feature** (dashboard-configured fixed phone number → fixed code, skips real SMS entirely) for manual verification, combined with mocked `supabase.auth.signInWithOtp`/`verifyOtp` calls in the automated test suite (already the design doc's plan). This exercises the entire app-side flow (validation, UI, session persistence, auth-guard redirect) without needing MSG91/Twilio/DLT resolved. BL-001 itself remains open — this only unblocks *building and verifying app logic*, not real OTP delivery, which still needs the business decision.

No MCP tool exposes Supabase Auth provider/Test-OTP configuration (confirmed by searching available Supabase MCP tools) — that dashboard step remains manual for the user.

**Non-trivial test-infrastructure issues found and fixed while getting these green** (new gaps beyond the design doc, discovered by actually running the suite — same category as SS-008's Developer-phase discoveries):
1. **`@testing-library/react-native@14.0.1`'s `renderHook`/`fireEvent.*` are now `async`/return `Promise`s** (not documented anywhere in this repo, differs from most examples): `renderHook(...)` must be `await`ed to get a populated `result` ref, and `fireEvent.changeText`/`fireEvent.press` must be `await`ed before a subsequent `fireEvent` call can rely on the resulting state update having flushed — chaining two un-awaited `fireEvent` calls back-to-back (e.g. `changeText` then `press`) reads stale pre-update state, and additionally corrupts *every subsequent test in the same file* (observed as "unable to find element" failures on later, unrelated tests, with a `console.error` "You seem to have overlapping act() calls" pointing at the cause). Fixed by `await`-ing every `renderHook`/`fireEvent.changeText`/`fireEvent.press` call across all new test files.
2. **Mixing `jest.useFakeTimers()` (set globally in `beforeEach`) with this RNTL version's `async render()`** silently breaks `render()`'s own internal flush for any test after the first couple in the same file (same "unable to find element" symptom as above, independent cause). Fixed in `verify-otp.test.tsx` by scoping `jest.useFakeTimers()`/`jest.useRealTimers()` to only the one test that actually needs fake timers (the resend-countdown test), leaving the rest on real timers.
3. **Back-to-back `render()`/`renderHook()` calls in the same file need an explicit `await cleanup()` in `afterEach`** (not automatic in this RNTL version, unlike some older setups) — without it, a still-mounted previous test's component stays subscribed to shared singletons (Zustand's `useAuthStore` in particular), producing "not wrapped in act()" warnings and, in `auth.store.test.ts`'s case, a `result.current` that never left its initial `null` ref value on the 3rd+ `renderHook` call in the file. Added `await cleanup()` to every new test file that calls `render`/`renderHook` more than once.
4. **A `jest.mock()` factory that references a `const mock*` variable directly as a property value** (e.g. `signInWithOtp: mockSignInWithOtp`) **races against that variable's own top-level `const` declaration**, since `jest.mock()` calls are hoisted above all other top-level code in the file, including the `import` statements whose transformed `require()` calls trigger the factory to actually run. `auth.service.test.ts`'s initial draft hit this (silently — no thrown error, unclear failure symptoms). Fixed by wrapping every mock reference in a deferred arrow function (`signInWithOtp: (arg) => mockSignInWithOtp(arg)`), which only reads the variable at *call* time (by then long-initialized), not at *factory-eval* time — the same indirection pattern already used correctly elsewhere in this file for the `auth.queries.ts`-consuming test files.
5. Biome's `lint/correctness/useExhaustiveDependencies` flagged `hooks/useSmsAutoRead.ts`'s `[onCodeReceived]` dependency (design doc's own exact code) as unnecessary, since the stub's effect body doesn't call it yet. Added a single-line `// biome-ignore lint/correctness/useExhaustiveDependencies: ...` directly above the `useEffect` (a multi-line comment block immediately above did *not* suppress it — Biome only recognizes a single-line `// biome-ignore rule: reason` comment as the actual suppression annotation).

None of these are design-doc mismatches — they're implementation-level testing-library/tooling behavior this repo hadn't exercised yet (SS-008's tests never chained `fireEvent` calls or mixed fake timers with multiple renders in one file).

## Manual Verification (user, in browser)

User ran `npx expo start --web` and hit a hard crash before reaching any screen: `TypeError: ExpoSecureStore.default.getValueWithKeyAsync is not a function`, killing the dev server process entirely.

**Root cause (BL-021, found and fixed directly, not via a subagent phase):** `mobile/lib/supabase.ts` creates the Supabase client at module scope, which immediately reads a session via `expo-secure-store` — a native-only module. `mobile/app.json` has `web.output: "static"`, which makes Expo Router pre-render routes in Node.js (even in dev mode), and `expo-secure-store` cannot execute there at all, crashing the server the instant `lib/supabase.ts` is imported. Confirmed against Expo's own tracked GitHub issues (same exact error string). Fixed by making the storage adapter platform-conditional: `localStorage` (guarded for the SSR/Node pass, where it's also undefined — safe no-op, real browser takes over on hydration) on web, `expo-secure-store` on native — the documented pattern for this class of issue. Verified: `tsc` clean, relevant tests (`lib/supabase.test.ts`, `features/auth/*`) still pass, dev server now returns HTTP 200 with real rendered content. Logged as **BL-021**, Resolved.
