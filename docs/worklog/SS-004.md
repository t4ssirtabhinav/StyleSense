## Developer — fix pass, 2026-07-22

QA's "PASS PENDING MANUAL VERIFICATION" verdict held for automated checks, but the user's actual manual walkthrough surfaced three real bugs QA's Read/Grep/Bash-only checks couldn't catch. **Bug 1 (CRITICAL — the actual QA-blocker): taxonomy chips showed "no options available" despite seeded DB rows.**
Root cause (confirmed live against the actual Supabase project): `style_keywords`/`occasion_types`/`colour_palette` are RLS-protected, and an anonymous/unauthenticated read resolves **successfully** with empty arrays rather than erroring. `useOnboardingTaxonomiesQuery()` (`mobile/features/onboarding/onboarding.queries.ts`) had no `enabled` gate tied to auth state, combined with `staleTime: 24h` / `gcTime: Infinity` — a single pre-auth fire permanently poisoned the `['onboarding','taxonomies']` cache with an empty "success" result for the rest of the app session, even after later authentication.
Fix: gated the hook on `enabled: Boolean(session)`, reading `useAuthStore`. No second defense (e.g. treating all-three-empty as itself suspicious) was added — the `enabled` gate closes the actual hole, and stacking a second heuristic on top would be over-engineering an already-closed gap.

**Bug 2: Step 1 "Next" silently no-op'd for a session-less visit.**
`/onboarding` is in the `(auth)` route group, which (unlike `(tabs)`) has no Auth Guard, so it's reachable without a session by design (direct URL entry, etc.). `handleNext`'s `if (!userId) return;` failed silently with zero feedback.
Fix: added an `isSessionLoading`/`!session` gate at the top of `OnboardingScreen`, mirroring `app/(tabs)/_layout.tsx`'s existing Auth Guard pattern exactly — a loading `Card` while `isSessionLoading`, then `<Redirect href="/login" />` when there's definitively no session, placed before all other render branches (including `showResumePrompt`). Kept `handleNext`'s `if (!userId) return;` as a deliberate defensive/type-narrowing check (documented inline) rather than deleting it — `userId`'s declared type is `string | undefined`, and the check is now unreachable-in-practice but cheap insurance against a future reordering of the guard.

**Bug 3: OTP boxes gave no visual focus indication (cross-ticket: component originates in SS-008, consumed by SS-003's verify-otp.tsx, fixed here per the BL-014/015/016/021 precedent of fixing a blocking bug directly rather than waiting for its origin ticket to reopen).**

Fix: added `isFocused` state via the hidden `TextInput`'s `onFocus`/`onBlur`, and highlighted the box at `index === Math.min(value.length, length - 1)` (the "next digit lands here" position) when focused. Reused existing tokens/conventions rather than inventing a new focus colour: border colour `colors.accent.peacock` (already the interactive-accent used for `Button`'s secondary variant border) and `border-2` width (already `Badge`'s `selected` convention for "this one is active").
