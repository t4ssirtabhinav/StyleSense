- Decision (AC-required): no new onboarding field added; skin tone/height stay deliberately uncollected per existing BL-027 reasoning.
- Decision (AC-required, BL-026): ship the backend foundation (port + mock adapter + stub router) now; the mobile-side "first suggestion" reward screen is explicit follow-up scope (new backlog row), not built in this backend-only ticket.
- Rate limiting: `RateLimiter` wraps Upstash's REST API via `httpx` (already a dependency); fails open (logs a warning) while `UPSTASH_REDIS_REST_URL`/`TOKEN` stay unset, as they are today — flagged as unacceptable once a real, costed adapter replaces the mock.
- Found and flagged rather than silently building: **no backend JWT-verification dependency exists anywhere in this repo yet** (SS-002/003 only built Supabase auth frontend/DB-side). This ticket's router uses a clearly-labeled non-production stub dependency instead of guessing at real Supabase JWT verification (legacy HS256 secret vs. JWKS — genuinely unverified, no web-fetch tool this pass).

Router tests therefore assert directly after the request call, no polling/synchronization primitive needed, per the design doc's contingency instruction.

**Design-doc deviations**:
- `app.dependency_overrides[IStylingProvider]` (as literally named in the design doc's test plan) doesn't work as a FastAPI override key here — FastAPI's `dependency_overrides` keys on the actual callable passed to `Depends(...)`, not on a type annotation, and `IStylingProvider` (an ABC) can't itself be used as a callable default. Used the idiomatic FastAPI pattern instead: a `get_styling_provider()` factory function is the `Depends()` key, overridden in tests via `app.dependency_overrides[get_styling_provider]`. Functionally proves the same thing (port swappable without touching the router file) — flagging the wording mismatch, not a scope gap.
- Added a `GenerateSuggestionsRequest` Pydantic body model (`style_preferences: dict | None`) to the router — not explicitly specified in the design doc (which didn't define a request body shape), needed so the endpoint has something to normalize/pass through. Kept minimal and consistent with the nullable-JSONB shape described in "Edge cases."
- Two pre-existing (not introduced by this ticket) lint/type failures blocked `ruff check .`/`mypy .` from passing repo-wide: `backend/models.py`'s unused `Optional` import, and `main.py`'s untyped `health()`. Fixed both as trivial, no-behavior-change corrections (see "Files modified" above) rather than leaving the required check red.
