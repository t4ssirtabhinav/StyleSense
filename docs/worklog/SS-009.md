**Design deviations:**
- `backend/main.py`'s `release=f'stylesense-backend@{app.version}'` (design's literal text) isn't executable as written — `sentry_sdk.init()` runs *before* `app = FastAPI(...)` is constructed in this file, so `app.version` doesn't exist yet at that point. Used a module-level `APP_VERSION = '0.1.0'` constant instead (single source of truth, also fed into `FastAPI(version=...)` and `/health`'s response), same resulting value.
- `lib/analytics.ts`'s `capture()` needed an explicit cast (`Parameters<PostHog['capture']>[1]`) to satisfy `tsc --noEmit` — `posthog-react-native`'s public entrypoint doesn't re-export `PostHogEventProperties` (only the undeclared transitive `@posthog/core` does), so the type was derived structurally off `PostHog.capture()`'s own signature instead of importing from a non-declared dependency.
- `sentry_sdk` 2.x's `Client.is_active()` returns `True` for any real `_Client` instance regardless of `dsn` (only the pre-init `NonRecordingClient` reports `False`) — the backend test's DSN-absent case sets `SENTRY_DSN_BACKEND=""` (not `delenv`) so `main.py`'s own `load_dotenv(override=False)` can't silently repopulate it from the repo's real root `.env` on module reload, and an autouse fixture resets the global client to a fresh `NonRecordingClient` before/after each test for isolation.
