**Expo Router `<Tabs>` API verification (key task item #1)**: read `node_modules/expo-router/build/layouts/TabsClient.d.ts` and `build/react-navigation/bottom-tabs/types.d.ts` directly before writing any code, per `mobile/AGENTS.md`. Confirmed the installed `expo-router@~56.2.11`: `Tabs` accepts a `tabBar?: (props: BottomTabBarProps) => ReactNode` prop where `BottomTabBarProps = { state, descriptors, navigation, insets }` — exactly the shape the design doc assumed. Also confirmed (via the real, unmocked `BottomTabBar.js` shipped in the package) that pressing an already-focused tab is a no-op re-navigation (emits `tabPress`, only dispatches `navigate` if `!focused`) — matches the design's "pressing focused tab is a no-op" assumption. **One deviation from the design doc's literal text**: `BottomTabBarProps` is not re-exported from `expo-router`'s top-level entry point (only from an internal, undocumented build path) — rather than deep-importing that internal path, `navigation.types.ts` derives `CustomTabBarProps` structurally from the public `Tabs` component's own `tabBar` prop type (`Parameters<NonNullable<ComponentProps<typeof Tabs>['tabBar']>>[0]`), which resolves to the identical shape without relying on an unstable import path. Also found and logged **BL-032**: `Tabs` from `expo-router`'s top level is marked `@deprecated` in favour of `expo-router/js-tabs`'s newer declarative API, but is still fully functional in this version — used it as designed rather than a larger out-of-scope navigation rewrite.

**SafeAreaProvider (key task item #2)**: mounted in `app/_layout.tsx` as instructed. Note for QA: `CustomTabBar` itself does not call `useSafeAreaInsets()` directly — it receives `insets` already computed via the `tabBar` render-prop (confirmed from `BottomTabBarProps`'s own type), so the literal "hook throws" scenario doesn't apply to `CustomTabBar` specifically. The mount is still required and correct: the underlying `<Tabs>` navigator (`BottomTabView`/`SafeAreaProviderCompat`) computes those real insets via the same hook internally, and a missing ancestor `SafeAreaProvider` would silently fall back to zeroed initial-metrics insets rather than real device values.
