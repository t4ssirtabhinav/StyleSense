### Architect — 2026-08-15 (Opus)

**Verdict: `Risk: high` confirmed** (unchanged from the raw ticket). Full lane. Design doc: `docs/tickets/SS-071-design.md`. Tier: standard.

**Ground-check confirmed today's live `BL-168` reproduction, line by line.** `(tabs)/_layout.tsx:30-58` guards session presence only; `login.tsx:23-86` never reads `useAuthStore`; there is no `app/(auth)/_layout.tsx`; `verify-otp.tsx:55-65` is the sole forward-routing site. Also verified provider-agnostic claims hold (`users.phone`/`email` both nullable `UNIQUE`, RLS is `auth.uid()`-based, zero `session.user.phone` reads anywhere in `mobile/`).

**Key decisions:**
- **Mechanism (b): route-layout guards, one shared decision function.** New `features/auth/useAuthRouting.ts` returns `loading | unauthenticated | onboarding | app`; only layouts navigate. Forced by AC #4 (cold open touches no auth screen) and by a mechanical AC #1 constraint: `login.test.tsx` mocks `expo-router` as `{ useRouter }` only and renders bare with no `QueryClientProvider`, so any session-awareness *inside* `login.tsx` breaks the tests AC #1 requires to pass unmodified. A new `app/(auth)/_layout.tsx` satisfies both.
- **`/onboarding` deliberately excluded from the `(auth)` guard.** Makes a redirect loop structurally impossible (no route is both source and target), preserves SS-016's direct-entry handling, and avoids duplicating `onboarding.tsx`'s existing session guard.
- **`verify-otp.tsx` ends up performing no navigation at all** — a test asserts `router.replace` is never called, so the two mechanisms cannot both ship.
- **`[VERIFIED 2026-08-15 against installed `@supabase/auth-js` typings]` `signOut()` defaults to `scope: 'global'`** — the SDK's own doc comment warns this signs the user out on *every device*. Design mandates `{ scope: 'local' }`. It resolves `{ error }` rather than throwing. Left as an explicit Developer verification task: whether a *failed* revoke still clears persisted storage.
- **Exhaustive store enumeration for AC #6: six stores across four files** (auth, onboarding, 3× wardrobe, outfit-ai) — the raw ticket's "style-score store" **does not exist**. Two need repair: `useWardrobeUploadStore` has **no `reset()`**, and `useOutfitAiStore`'s `resetDeck()` clears 1 of 4 fields. Self-registration registry (`registerUserStateReset`) so a future store's omission fails next to the store.

**Blockers: none.** Entirely local `mobile/` work; no provisioning, schema, or third-party config. Two things the Developer must verify rather than assume: `usePathname()`'s real runtime value (`/login` vs `/(auth)/login` — a naive match makes the guard silently never fire, reintroducing `BL-168` with all tests green), and the `signOut` failure branch above.

**Flagged for the user (not fixed):** onboarding's `Skip` does `replace('/')` without setting `onboarding_completed`, so AC #4 makes such users hit `/onboarding` on every cold open. Pre-existing Skip semantics, but AC #4 is what makes it reachable — "does Skip mean done or later?" is an onboarding-product call, not an auth one.
