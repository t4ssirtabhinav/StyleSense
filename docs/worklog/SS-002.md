**Explicitly not executed against a live database** — these tests are written to be correct and runnable per the design doc's spec, but have NOT been run against the actual `mefpfykuinasgkpfhmzk` project or a local Supabase stack. Whoever picks this up next needs `pip install psycopg2-binary` in `backend/venv` plus a `SUPABASE_DB_URL` env var (direct Postgres connection string, `postgres` role, from Supabase Dashboard → Project Settings → Database) to actually run them.

**`mobile/__tests__/types/supabase-types.test.ts`** (new) — runtime shape assertions (not just compile-time types) against `Constants.public.Enums` in the generated types file: `wardrobe_category` has exactly 21 members matching the exact value list/order, `plan_tier` has exactly 3, `occasion_type` has exactly 12. **`mobile/__tests__/lib/supabase.test.ts`** (new) — added per the design doc's conditional instruction ("only add it here if the Developer finds `lib/supabase.ts` itself lacks any coverage yet") — confirmed no existing test covered it (only `__tests__/sanity.test.ts` existed beforehand). User decision: merged PR #7 manually despite red CI (given the failure is an unrelated infra bug, not a code defect in this ticket), and asked for the CI permissions gap to be fixed separately in a follow-up PR. Merged as commit `4c1274a` into `develop`.
