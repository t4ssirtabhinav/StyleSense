**Key decisions**
- **Fetch lives in FastAPI, not a Supabase Edge Function** — deliberate contradiction of the raw ticket's first sentence. Decisive reason: an Edge-Function-plus-client round trip lets untrusted client input drive a styling exclusion and reach an LLM prompt. Also: prompt builder / cache signature / eligibility stage / Upstash client are all Python; `BL-042` (no Deno CI) and `BL-045` (no Edge Function rate limiting) both argue the same way. Reversible — it sits behind `IWeatherProvider`. **Open Question #1, wants a human nod.**
- **AC #3 is a code-level filter, not a prompt hint** — `engine_v2_eligibility.filter_eligible(weather=…)` unions `{"white"}` into the existing `effective_excluded` set (so `item_is_hard_excluded_white` and its HSV thresholds are reused verbatim — one definition of white in the codebase) and drops `fabric == "silk"` by exact key match, safe because migration `016`'s trigger normalises `wardrobe_items.fabric` on write (`raw_silk`/`tussar_silk`→`silk`; `art_silk`→`rayon`, correctly *not* excluded). **Relax-if-empty guardrail** is mandatory: an all-white-silk wardrobe in heavy rain gets its suggestions back with `weather_exclusions_relaxed=True`.
- **`compute_narration_signature` gains a required `weather_bucket`** (coarse: 3 condition classes × 5 °C bands; humidity excluded). Without it, monsoon prose gets served on a clear day. Consequence flagged loudly per SS-020's own instruction: every existing `suggestion_narration_cache` row goes stale (TTL ≤ 6 h, no data loss, no migration) and SS-020's golden-file signature test must be updated in this PR.
- Verified against the repo, not assumed: `users.city` exists (`001_initial.sql:29`) and is written by SS-004 Step 1 — but stores the **display name**, and the picker's "Other" row stores arbitrary free text. Hence a transcribed 50-city coordinate table + short alias map, and no geocoding fallback.
