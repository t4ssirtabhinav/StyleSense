- Near-white threshold (`BL-111`) moves to `app_config` key `near_white_threshold` (coded default 0.92/0.12, identical to today) with a per-occasion override via two new `StylingRulesOverride` fields — migration `017`, data-only.
- Colour star-topology fixed via `pairwise_colour_harmony` (all-pairs, not vs. item[0]) — resolves `BL-128`'s star-topology half; the flat `0.75` unparsable-colour fallback is **explicitly re-deferred**, still blocked on `BL-064`/`BL-079`'s hex→colour-family binning, which remains unbuilt.
- `garment_registry_adapter`/`fabric_registry_repository` use `service_role` (new, documented deviation mirroring `IAppConfigRepository`'s existing precedent) since `get_garment_attributes(category: str)` must be callable with no `jwt` in hand, inside the hot scoring loop.
- Since no live `wardrobe_items.category` value currently resolves through `garment_types` (SS-034 seeded new-vocabulary keys, not the 21-value enum), `volume_balance`/`register_coherence`/`BL-129`'s ranking fix are architecturally correct and unit-tested but **100% live-inert today** — flagged explicitly rather than silently assumed working (new `BL-132`).
- `fabric_weather` scoring ships gated per sub-signal (not per fabric row): `season_affinity IS NULL` (silk, khadi — `BL-125`'s flagged rows) skips only that sub-signal; `weight`/`breathability` still contribute. Satisfies the ticket's own "ship gated" option without a stylist review happening inside this ticket.
