Key implementation decision not spelled out verbatim in the design doc: `StylingRulesOverride`'s per-field leniency is implemented as a `parse_lenient(raw: dict) -> StylingRulesOverride` classmethod (uses `pydantic.TypeAdapter` per field, catching `ValidationError` and dropping to `None`) rather than a `field_validator`-per-field approach — a bare `mode="before"` validator that just returns the value unchanged does not actually achieve "wrong-typed value dropped to `None`" (Pydantic still raises during normal field coercion), so `parse_lenient` is the mechanism that makes `test_malformed_styling_rules_degrades_without_raising` true. `_resolve_styling_rules` calls `parse_lenient` then layers successfully-parsed fields over the kind default exactly as specified.
