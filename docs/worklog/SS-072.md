**The insight that kept this small.** Confirming an account is done **by GoTrue, server-side, the moment the emailed link is opened in any browser** — the redirect afterwards only auto-signs-in the clicker. So a complete flow exists with **zero new routes, zero deep-link config, and no `lib/supabase.ts` change**: signup → "Check your email" state → user opens link → returns to the app and **signs in**. One extra user action buys the ticket out of new external redirect surface.

**Key decisions.**
1. **`signUpWithEmail` stops throwing on `session === null`.** Return contract becomes `EmailSignUpResult = { status: 'session'; session } | { status: 'confirmation_required'; email }`. The null session is a *success*. The `'session'` arm is kept (currently unreachable) so a future Confirm-email flip needs no edit. `signInWithEmail` unchanged.
2. **New `features/auth/components/CheckYourEmailNotice.tsx`** — a state of `EmailAuthForm`, not a route (preserves Deviation 1). Two entrances: signup returning `confirmation_required`, and sign-in failing `email_not_confirmed`. Three controls: **Resend** (`resend({ type: 'signup', email })`, 60s client cooldown, server limit → SS-003's existing `rate_limited` copy), **Wrong email? Start over**, **Sign in instead**.
3. **`BL-173` sharpened → ship the "start over" affordance (new AC #13).** A mistyped address is otherwise a permanent dead end. Stated honestly in the design: it lets the user re-register with their *correct* address; it does **not** release the mistyped one.
4. **AC #3 reconciled, as the raw ticket's Technical Notes pre-authorized.** Split into a hard half (raw `Database error…`/bare 500 never reaches the user; a `Sign in instead` control present in *every* duplicate-reachable state) and a conditional half (the specific copy wherever Supabase returns an identifiable duplicate). Deliberately **not** unmasking GoTrue's obfuscated response via the `identities.length === 0` heuristic — undocumented shape-branching that defeats a platform anti-enumeration measure for no UX gain.
5. **AC #14 (new):** `email_not_confirmed` on sign-in routes to the notice, not "Incorrect email or password." AC #7's asymmetry re-accepted deliberately — now a common path, not a defensive one.
6. Revised ACs #2/#3 + new #12/#13/#14 live in the **design doc**, which is authoritative for QA. Raw ticket not edited (Ticket Design mode doesn't rewrite raw tickets) — a human may amend it.
