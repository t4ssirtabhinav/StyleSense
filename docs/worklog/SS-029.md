**Key implementation decisions not fully pinned by the design's prose pseudocode** (§4.1/§4.2 are illustrative, not literal signatures):
1. **`CostBudgetGate.reserve()`/`.reconcile()` exchange a `Reservation` dataclass**, not a bare micropaise int as §4.1's pseudocode shorthand implies. It carries `daily_key`/`monthly_key`/`daily_current`/`monthly_current`/`daily_ceiling`/`monthly_ceiling` alongside the reserved amount, so `reconcile()` can compute the post-reconcile expected counter value and emit `budget_ceiling_exceeded` (§4.4) from pure arithmetic, without a second Redis round-trip. Threaded router → `BackgroundTasks` → service unchanged, exactly as the design's data-flow describes.
2. **Ledger writes get a second, service-level `try/except`** on top of `ICostLedger.record`'s own "never raises" contract (`SupabaseCostLedger` already guarantees it). The design's own test plan names `test_ledger_failure_does_not_break_the_tagging_pipeline` — pinned as "tags still written" even against a hypothetically misbehaving `ICostLedger` implementation, so both services wrap the call defensively (log `ledger_write_failed`, continue) rather than trusting the port contract alone.
3. **`gemini-3.5-flash-lite`'s token usage is real, not the `default_tokens_*` fallback** — the live verification script's real Gemini call returned `usage_metadata.prompt_token_count=1839`/`candidates_token_count=147`, proving `_extract_usage`'s field names are correct against the actual API response, not just the SDK's declared type shape.
