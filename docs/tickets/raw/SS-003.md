# SS-003 — Phone OTP Authentication Flow (India-First)

`[Feature]` `[P0]` `[Sprint 1]` `[2 pts]` Est: 8h
Depends on: SS-002

## Description

Build complete phone-first authentication flow. India users overwhelmingly prefer phone login over email.

**Screen 1 — Phone Input:** App branding (StyleSense logo, warm off-white bg, marigold CTA). Country code defaulting to +91 (selector available). 10-digit validation (starts with 6/7/8/9). CTA: "Send OTP". Loading state. Error handling for invalid numbers and rate limits.

**Screen 2 — OTP Verification:** 6-digit input with individual boxes, auto-focus advancement, auto-read SMS on Android (`expo-sms-retriever` or similar). Auto-submit on 6th digit. 30-second resend cooldown timer. Handle wrong OTP (shake + error), expired OTP (prompt resend). On success: session persists via `expo-secure-store`.

**Auth Guard:** Wrap `(tabs)` layout in a session check. No valid session → redirect to login. Session expiry redirects gracefully without data loss.

## Acceptance Criteria

- Phone input validates 10-digit Indian mobile number (starts with 6, 7, 8, or 9)
- Auto-read OTP from SMS on Android (no manual typing required)
- 6-digit OTP input auto-advances focus between boxes on each digit entry
- Entering correct OTP creates a Supabase session stored in `expo-secure-store`
- Wrong OTP shows inline error with shake animation; does not crash
- Resend button disabled for 30 seconds; timer counts down visibly
- After auth, user is redirected to onboarding (first login) or home (returning user)
- JWT stored securely in SecureStore (Expo)
- Session persists across app kills; a valid session skips login on reopen
- Graceful error for invalid numbers

## Technical Notes

- `supabase.auth.signInWithOtp({ phone: '+91XXXXXXXXXX' })` — always prepend country code
- Store session using Supabase's built-in `expo-secure-store` adapter
- Auth state listener: `supabase.auth.onAuthStateChange()` in root `_layout.tsx`
- OTP input: single hidden `TextInput` with `keyboardType='number-pad'`, map chars to visual boxes

## Edge Cases & Failure Modes

- SMS not received after 30s: offer "Resend" and note "Check if DND is active on your number"
- User on airplane mode: show "No internet connection" message, not a crash
- Keyboard covers OTP input on small screens: `KeyboardAvoidingView` required
- Copy-paste OTP from SMS: if user pastes 6 digits at once, all boxes fill and auto-submit
- Landline number (starts with 0 or 2): show "Please enter a mobile number" error
