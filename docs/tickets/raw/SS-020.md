# SS-020 — Claude Outfit Suggestion API Endpoint

`[Feature]` `[P1]` `[Sprint 5]` `[3 pts]` Est: 8h
Depends on: SS-002, SS-006, SS-012

## Description

`POST /ai/outfit-suggest` on FastAPI. Build wardrobe context from DB (serialise items as JSON with category/colour/occasion metadata). Inject Indian fashion system prompt (ethnic colour rules, occasion logic). Claude Sonnet call. Parse structured JSON response: 3 outfits with `item_ids`, reasoning, scores. Redis cache by `(user_id + occasion + wardrobe_hash)`, 4hr TTL.

This is the first ticket to implement `IStylingProvider` for real (SS-006 shipped the port + `MockStylingAdapter` + stub router only) — a new `ClaudeStylingAdapter` implements the existing port per CLAUDE.md's Open/Closed rule (never modify the port for a new provider).

## Acceptance Criteria

- Returns 3 valid outfit combinations using actual wardrobe item IDs (not hallucinated)
- Each outfit includes AI reasoning in English or Hindi
- Occasion-appropriate — white not suggested for `wedding_guest`
- Cache hit returns under 200ms; cold call under 4s
- Graceful fallback if Claude API is down (return cached or basic rule-based selection, never a hard error to the user)
- Free tier: max 3 calls/day enforced server-side (Upstash Redis, fail-closed)

## Technical Notes

- `ai/adapters/ClaudeStylingAdapter.py` implements `ai/ports/interfaces.py::IStylingProvider` (already defined by SS-006) — swap-in, not a port change
- Background task pattern (no synchronous AI calls), per CLAUDE.md
- Log all AI calls: `user_id`, `tokens_used`, `latency_ms`, per CLAUDE.md
- Rate limiting: reuse SS-018's Upstash fail-closed pattern, not a new implementation
- `wardrobe_hash` for the cache key needs a stable serialization of the queried item set — define this once, don't let it silently drift per caller

## Edge Cases & Failure Modes

- `style_preferences: null` (user skipped onboarding) — degrade to generic/popular suggestions, per SS-006's spec, not an error
- Wardrobe has fewer than 3 items in the relevant occasion category — return what's available with an honest "limited options" flag, not padded/invented items
- `pattern`/`fabric` tags are free-text with no canonical vocabulary (`BL-064`, still open) — prompt should treat these as advisory hints, not hard filters, since an unexpected string shouldn't silently exclude an item
- Claude API latency/availability — same class of risk SS-011/SS-012 hit with Replicate/Gemini (`BL-058`/`BL-067`): verify the "<4s cold call" AC against a real call with a real (non-trivial) wardrobe, not a synthetic 1-item case, before claiming it passes
