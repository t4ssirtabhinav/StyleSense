# SS-004 — User Onboarding Wizard (4-Step, Skippable)

`[Feature]` `[P0]` `[Sprint 1]` `[2 pts]` Est: 8h
Depends on: SS-003

## Description

After first login, a 4-screen onboarding wizard. Horizontal FlashList pager. Each step is skippable (skip button per step) — incomplete-onboarding users still land on home. Can return to complete from Profile settings.

- **Step 1 — Basic Profile:** Name, gender (Woman/Man/Non-binary/Prefer not to say), city picker (top 50 Indian cities, searchable + "Other").
- **Step 2 — Style & Wardrobe:** Multi-select style keywords (Ethnic, Western, Indo-Western, Casual, Formal, Streetwear, Bohemian, Minimalist, Maximalist) + wardrobe description (Mostly Western / Mostly Ethnic / Equal Mix / Mostly Formal / Mostly Casual).
- **Step 3 — Occasion Priorities:** Tap to select top 3 occasions (Office, Wedding, Festival, Casual, Date, Party, College, Travel, Puja).
- **Step 4 — Budget Range + Colour Preferences:** Budget selector (₹500–1k / ₹1k–3k / ₹3k–10k / ₹10k+). Colour palette (12 colour circles, multi-select up to 5). On "Get Started": save to `users` table and `style_preferences` JSONB.

## Acceptance Criteria

- 4-step wizard with horizontal swipe navigation and step indicator dots
- Each step is skippable; skip lands on home with an incomplete profile
- Can return to complete onboarding from Profile → Edit Preferences
- Step 1 collects name, gender, city; city picker searches top 50 Indian cities
- Step 2 allows multi-select of style keywords + wardrobe type
- Step 3 allows selecting top 3 occasion priorities
- Step 4 has budget range selector and 12-colour-circle multi-select
- "Get Started" saves all data to `users` table and `style_preferences` JSONB
- All screens use design system tokens: warm off-white bg, Poppins headings, marigold CTAs

## Technical Notes

- `FlashList` (`@shopify/flash-list`) with `horizontal`, `pagingEnabled` for the pager — per project standard, `FlatList` is never used
- City data: hardcode top 50 Indian cities with lat/lng for weather API later
- `style_preferences` JSONB shape: `{ styles[], wardrobe_type, occasions_priority[], budget_range, favourite_colours[], gender }`
- **Option taxonomies must not be hardcoded TS unions.** `style_keywords`, `occasion_types`, and the 12-swatch `colour_palette` are the three lists most likely to expand post-launch (new regional festivals, new aesthetic categories) — ship these as DB-backed reference tables (`key`, `label`, `sort_order`, `active`), fetched once and cached client-side, so product can add/retire options without an app-store release. `gender`, `wardrobe_type`, and `budget_range` are structurally stable and may stay as hardcoded unions.

## Edge Cases & Failure Modes

- User kills app mid-onboarding: on next login, check `users.full_name IS NULL` to detect incomplete state; show a resume prompt
- User selects "Other" city but doesn't type: require non-empty input before Next
- Small screen (5-inch): colour circles fit a 4x3 grid without horizontal scroll within the step
