# SS-017 — Migrate Off Deprecated `expo-router` `Tabs`/`tabBar` API

`[Task]` `[P2]` `[unscheduled — backlog-driven]` `[2 pts]` Est: 5h
Depends on: none (isolated to the tab-bar shell)
Risk: low

## Source note (this repo)

Resolves `BL-032` (SS-005/Developer, 2026-07-22). Not from the original epics doc — a tech-debt item found while implementing SS-005's bottom tab navigation. The installed `expo-router@~56.2.11`'s own `.d.ts` marks the render-prop `Tabs`/`tabBar` shape used by `CustomTabBar` as `@deprecated` in favour of `expo-router/js-tabs`'s `TabList`/`TabTrigger`/`TabSlot` primitives. Still fully functional today — this is proactive debt paydown, not an urgent fix (backlog note: "revisit before `expo-router` is next upgraded past 56.x"), started now because it's isolated and low-risk enough to run alongside other quick wins.

## Description

`mobile/app/(tabs)/_layout.tsx` currently does:

```ts
import { Redirect, Tabs } from 'expo-router';
...
<Tabs tabBar={(props) => <CustomTabBar {...props} />}>
```

Migrate to `expo-router/js-tabs`'s declarative `TabList`/`TabTrigger`/`TabSlot` primitives, preserving `CustomTabBar`'s existing visual behavior exactly: 64px height, warm off-white background, marigold active icon, muted inactive, dot indicator below the active icon, safe-area inset handling, haptic feedback on tap.

## Acceptance Criteria

- All 5 tabs (Home, Wardrobe, Style, Discover, Profile) render identically to today, pixel-for-pixel on the same visual checks SS-005's manual verification covered
- Active tab still shows the marigold icon + dot indicator; inactive tabs stay muted
- Tab bar still respects safe-area insets on notched/gesture-nav Android
- Deep links to each tab (`stylesense://wardrobe` etc.) still work
- Haptic feedback on tab tap is preserved
- No `@deprecated` warning from `expo-router`'s own types for this file
- Existing SS-005 tab-navigation tests still pass (adapted to the new primitives' testing shape as needed)

## Technical Notes

- Reference `expo-router/js-tabs`'s `TabList`/`TabTrigger`/`TabSlot` exports directly from the installed package's `.d.ts` (per `mobile/AGENTS.md`'s "Expo has changed" warning — verify against the installed version, not trained knowledge)
- `CustomTabBar`'s existing rendering logic (icon/dot/haptics/safe-area) should be portable into whatever slot/trigger customization `js-tabs` exposes — check its API surface for where custom tab-item rendering hooks in before assuming a full rewrite is needed
- This is confined to `app/(tabs)/_layout.tsx` and `features/navigation/components/CustomTabBar.tsx` — no route content inside any tab should need to change

## Edge Cases & Failure Modes

- If `js-tabs`' customization API can't reproduce a specific visual detail (e.g. the dot indicator) as cleanly as the render-prop API could: document the gap explicitly in the design doc rather than silently dropping it
- Confirm Android 3-button-nav vs. gesture-nav overlap behavior (SS-005's original edge case) still holds after the migration
