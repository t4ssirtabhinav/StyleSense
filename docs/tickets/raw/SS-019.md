# SS-019 — Fix SS-013 upload-flow regressions found in manual verification

`[Bug]` `[P0]` `[Sprint 4]` `[2 pts]` Est: 4h
Risk: med
Depends on: SS-013 (merged, PR #25), SS-012 (merged, PR #24)

## Description

Real-device/browser manual verification of the merged SS-013 upload flow (user-run, 2026-07-27)
surfaced a set of defects that the automated suite could not catch — every one of them passed
`tsc`/`biome`/`jest` because the failures live in *wiring between* correctly-unit-tested pieces,
or in layout that no test asserts.

The headline defect is that **Gemini's auto-tagging results never reach the review form**, so the
user is asked to hand-enter data the backend already computed and stored correctly.

## Root causes (already investigated — do not re-derive)

Verified by the orchestrator on 2026-07-27 by reading the merged code directly:

1. **Tags not prefilled in ReviewStep.** The DB row *is* populated correctly by SS-012 (user
   confirmed via Supabase dashboard). The break is entirely client-side:
   - `mobile/app/wardrobe/upload.tsx` (~L78-100): the Realtime `subscribeToItemUpdates` handler
     reads only `row.processing_status` and `row.ai_tags?.tagging?.status`. It never reads the
     tag columns (`category`, `subcategory`, `color_primary`, `color_secondary`, `pattern`,
     `fabric`, `occasion_tags`, `season_tags`).
   - `mobile/features/wardrobe/wardrobe.types.ts` (~L188-195): `WardrobeItemRealtimeRow` only
     declares `id`/`processing_status`/`ai_tags`, so TypeScript could not flag the omission —
     Supabase sends the full row, the type discards it.
   - `mobile/features/wardrobe/wardrobe.store.ts` (~L203): `updateItemTags(taskId, tags)` exists
     and works, but has **zero production callers** (grep-confirmed; only
     `wardrobe.store.test.ts` calls it).
   - Net effect: `currentItem.tags` is always `undefined`, so `upload.tsx` (~L237)
     `initialTags={currentItem.tags ?? DEFAULT_TAGS_DRAFT}` always falls back to the all-null
     default.
2. **Nested `<button>` console error on web.** `mobile/features/wardrobe/components/ItemCard.tsx`
   (~L66) is a `Pressable` with `accessibilityRole="button"` wrapping an `IconButton` (itself a
   button) at ~L75 — renders `<button>` inside `<button>` on web. (ItemCard is SS-014's file but
   the nesting pattern is the shared card/press convention; coordinate with SS-014's fix pass so
   the two don't collide — see Notes.)
3. **No scroll anywhere in the upload flow.** `upload.tsx` renders a bare fragment and
   `ReviewStep` is a plain `Card` — there is no `ScrollView`/`KeyboardAwareScrollView` in the
   tree, so on a laptop screen the form's lower half (occasion/season chips, "Looks Good!") is
   unreachable without browser zoom-out. Also blocks mobile-viewport inspector testing.
4. **Occasion/season chips stack vertically.** `ReviewStep.tsx` (~L207-226) maps `Badge`s
   directly into the `Card` with no `flex-row flex-wrap` container; React Native defaults to
   `flexDirection: column`, so 12 occasion + 4 season chips render as one long vertical column.

## Acceptance Criteria

- Gemini's tags (category, subcategory, both colours, pattern, fabric, occasion tags, season
  tags, confidence, content flag, contains-person) are **prefilled** in ReviewStep when tagging
  completes; the user edits rather than authors them
- `WardrobeItemRealtimeRow` carries the tag columns, and the Realtime handler maps them into the
  batch store via the existing `updateItemTags` action
- A low-confidence (`< 0.7`) result still prefills, and still shows the existing low-confidence
  banner
- Tagging that fails (`ai_tags.tagging.status === 'failed'`) falls back to the blank draft
  without crashing, and the user can still complete the review manually
- No nested-button console error on web anywhere in the upload or wardrobe flows
- The entire review form is reachable by scrolling at a 1366×768 laptop viewport and in a mobile
  device-emulation viewport, with no zoom-out required
- Occasion and season chips wrap horizontally rather than stacking one-per-row
- The review image sits in a visually distinct frame with spacing between it and the content
  below it (no edge-to-edge collision with the next section)
- CaptureStep's placeholder text is centred both axes, and a spinner/progress indicator is shown
  while an image is uploading/processing
- The post-save ("Looks Good!") screen shows a real summary state, not a blank screen with only a
  close affordance
- Existing SS-013 tests still pass; new tests cover the Realtime-row→store→ReviewStep prefill
  path end-to-end (the specific integration gap that let this ship)

## Technical Notes

- The prefill fix is the priority; the rest are layout/UX defects of the same verification pass.
- Add an **integration-level** test for the prefill path — the reason this shipped is that every
  unit was individually green while nothing asserted they were connected. A test that only mocks
  `updateItemTags` and asserts it was called would be enough to have caught it.
- `mobile/CLAUDE.md`/`AGENTS.md`: Expo has changed — read the versioned docs at
  https://docs.expo.dev/versions/v56.0.0/ before writing scroll/keyboard-handling code.
- Per CLAUDE.md: NativeWind `className` only (no `StyleSheet.create`), `components/ui/` wrappers
  only (no raw `View`/`Text`), handle loading/error/empty states.
