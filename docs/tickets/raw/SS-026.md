# SS-026 — Runtime Config Substrate (`app_config` + Feature Flags)

`[Infra]` `[P0]` `[Sprint 5]` `[3 pts]` Est: 14h
Depends on: SS-002
Risk: med

## Description

A server-side configuration store that lets us change AI model routing, cost budgets, provider quota ceilings, cache TTLs and pre-filter thresholds **without a deploy**, plus wiring for user-targeted feature flags.

This exists so that the single most expensive decision in the product — which model answers an outfit request — is a config row rather than an import. It is what makes SS-028's router tunable and what de-risks shipping before the AI provider eval completes (see [`EXECUTION-PLAN.md`](../../proposals/EXECUTION-PLAN.md) §3.4).

## Acceptance Criteria

- `app_config` table: `key`, `value JSONB`, `scope`, `description`, `updated_at`, `updated_by`
- Backend reads config through a single typed accessor with a short-TTL in-process cache — never a raw table read scattered across services
- Changing a config value takes effect within the cache TTL **with no redeploy and no restart**; demonstrated in QA
- Every config key has a **hardcoded safe default in code**. A missing, malformed or unreachable config row degrades to that default and logs — it never throws and never blocks a request
- Config reads are `service_role` only by default; a `client_visible` flag exposes a whitelisted subset to `authenticated`
- PostHog feature flags wired on both mobile and backend, with a typed wrapper
- Config changes are auditable — `updated_at`/`updated_by` populated

## Technical Notes

**Two mechanisms, deliberately separate — do not merge them:**

| Mechanism | Owns | Why |
|---|---|---|
| `app_config` (Supabase) | Model routing table, cost budgets, quota ceilings, pre-filter thresholds, cache TTLs | Server-side, atomic, auditable, needs to be consistent across instances |
| PostHog flags | Paywall copy/price A/B, feature rollout, tier-gated experiments | User-targeted, needs cohort logic |

PostHog flags also satisfy the epics doc's existing Sprint-5 requirement — *"A/B ready: paywall copy and pricing can be remote-configured"* — at no extra vendor cost (`[VERIFIED 2026-07-28]` PostHog free tier: 1M flag requests/month).

**Typed config, not stringly-typed.** Each key gets a Pydantic model. `value JSONB` parsed and validated on read; a validation failure falls back to the coded default and logs at error level. A config store that can silently ship a malformed model-routing table is worse than no config store.

**Cache TTL is itself a config key**, with a coded default — but never let a bad TTL value make config unreachable. Clamp it.

## Edge Cases & Failure Modes

- Supabase unreachable at boot → every key serves its coded default; the app starts. **Config must never be a startup dependency**
- Malformed JSONB in a row → that key falls back to default and logs; other keys unaffected. Never fail the whole config load on one bad row
- Config changed mid-request → a single request must see one consistent snapshot, not a value that changes between the router and the ledger
- Two instances with staggered cache expiry briefly disagree → acceptable for routing/budgets, **not** for anything requiring strict consistency. Document which keys tolerate skew
- A `client_visible` key accidentally exposing an internal budget or quota → whitelist is explicit and enumerated, never a wildcard or a negation
