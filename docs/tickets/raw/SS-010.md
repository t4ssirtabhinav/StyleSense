# SS-010 — Cloudflare R2 Presigned Upload Infrastructure

`[Task]` `[P0]` `[Sprint 3]` `[2 pts]` Est: 4h
Depends on: SS-002, SS-008

## Description

Image upload pipeline using R2 presigned URLs. The client never sends images through the backend — it uploads directly to R2. Supabase Edge Function: `get-upload-url`. Validates JWT, checks the wardrobe limit (50 free, unlimited premium), generates a presigned PUT URL (5-minute expiry). R2 key: `wardrobe/{user_id}/{item_id}/original.jpg`.

Client-side: compress to max 1200px width (`expo-image-manipulator`) before upload. Progress bar. On completion, `POST /wardrobe/items/process` to trigger BG removal + AI tagging.

## Acceptance Criteria

- Edge Function returns a presigned R2 PUT URL with 5-minute expiry
- Free users blocked after 50 items with an "Upgrade to premium" error
- Client compresses images to max 1200px width before upload
- R2 upload completes under 3s on 4G
- Upload progress is visible (percentage or progress bar)
- R2 key follows the `wardrobe/{user_id}/{item_id}/original.jpg` pattern
- Private bucket — URL requires signed access
- Upload failure shows a retry button with a user-friendly error

## Technical Notes

- Cloudflare R2: S3-compatible, 10GB free, zero egress fees
- `@aws-sdk/client-s3` with `getSignedUrl()` pointed at the R2 endpoint
- `expo-image-manipulator` for client-side compression

## Edge Cases & Failure Modes

- Slow 3G (common in Tier-2/3 India): retry with exponential backoff
- Very large image (20MB+ from DSLR): compress to under 2MB before upload
- Presigned URL expires mid-upload: detect 403, request a fresh URL, retry
- Hash-based dedup: check against existing items before processing
- Free user at 49 items uploads 1 — should succeed. 51st blocked.
