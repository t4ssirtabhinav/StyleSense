# SS-013 — Wardrobe Item Upload Flow UI (Single + Bulk)

`[Feature]` `[P0]` `[Sprint 3]` `[2 pts]` Est: 6h
Depends on: SS-010, SS-011, SS-012, SS-008

## Description

A 3-step upload UX — the most critical flow for activation. **Step 1 — Capture:** full-screen camera (`expo-camera`, rear default) + "Gallery" button. Gallery allows multiple selection up to 10 items for batch upload. **Step 2 — Processing:** shimmer overlay showing "Removing background..." then "Analysing your item...". Supabase Realtime subscription for completion. Tip during the wait. **Step 3 — Review & Confirm:** BG-removed image on a clean card. AI tags as editable chips (category dropdown, colours, occasions multi-select, fabric, pattern). "Looks Good!" one-tap accept or edit individual tags. Batch: process sequentially with progress (1/10, 2/10...). Success toast with "Add another" / "View wardrobe" options.

## Acceptance Criteria

- Camera opens rear default; tap to switch to front available
- Gallery allows selecting 1-10 images in a single session
- Camera/gallery permissions requested with an explanation; denial shows a settings redirect
- Processing shows real-time status updates (BG removal → AI tagging)
- Processing completes within 15 seconds for a single item on 4G
- Review screen shows the BG-removed image with all AI tags as editable chips
- Category editable via a dropdown with all 20 `wardrobe_category` values
- Batch upload processes sequentially with a progress indicator (1/10, 2/10...)
- "Looks Good!" saves the item and navigates to the grid; "Add another" restarts the flow
- Cancel at any step discards and returns to the wardrobe screen

## Technical Notes

- `expo-camera` for capture; `expo-image-picker` for gallery (multi-select)
- Supabase Realtime: subscribe to `wardrobe_items` filtered by `user_id` for processing updates
- Category dropdown: `BottomSheet` with a searchable list for the 20 categories

## Edge Cases & Failure Modes

- Camera permission denied permanently: "Open Settings" button linking to app settings
- Processing fails (API error): retry button, keep the original, allow manual tagging
- User closes the app during processing: item stays `processing`; resume check on next open
- Batch with one failure: continue the remaining items, show a failure count at the end
- Very slow network (2G): "This may take longer on slow connections" after 10 seconds
