## Description

Sentry for error/crash monitoring and PostHog for product analytics. Both initialised before any user interaction code runs.

**Sentry:** DSN, environment tag, release version, source maps upload in EAS build, user context (`user_id`, `plan_tier`) after login.

**PostHog:** implement all key analytics events: `install`, `register`, `first_item_added`, `first_suggestion_viewed`, `first_outfit_saved`, `premium_paywall_viewed`, `subscription_started`, `item_uploaded`, `outfit_shared`, `affiliate_link_clicked`, `tryon_generated`, `category_filtered`. Create a `useAnalytics()` hook. Set up a conversion funnel dashboard.

## Acceptance Criteria

- Sentry captures a test error visible in the dashboard within 30 seconds
- Sentry includes `user_id` and `plan_tier` in error context after auth
- PostHog records an `app_opened` event on launch, visible in the dashboard
- `useAnalytics()` hook tracks events with type-safe event names
- Source maps uploaded during EAS build; Sentry traces show TypeScript line numbers
- All 12+ key analytics events defined as typed constants (not magic strings)
- PostHog funnel: onboarding → first item → first suggestion → premium
- No PII in event properties (no phone numbers, no names)
- Backend: Sentry initialised in FastAPI; unhandled exceptions captured

## Technical Notes

- Sentry free tier: 5k errors/month. PostHog free tier: 1M events/month
- Analytics events are fire-and-forget; never `await` in UI code
- Disable PostHog capture in `__DEV__` to avoid polluting production data

## Edge Cases & Failure Modes

- Offline analytics: PostHog SDK batches locally and flushes when back online
