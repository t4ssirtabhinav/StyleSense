# SS-002 — Supabase Project Setup & Database Schema Migration

`[Task]` `[P0]` `[Sprint 1]` `[1 pt]` Est: 3h
Depends on: SS-001

## Description

Create Supabase project. Apply full DB schema from architecture LLD as initial migration (`001_initial.sql`). All custom ENUMs (`wardrobe_category` 20+ values, `plan_tier`, `occasion_type` 12 values), all tables (`users`, `wardrobe_items`, `outfits`, `suggestion_sessions`, `user_avatars`, `social_posts`, `shopping_wishlist`), computed columns (`cost_per_wear`), GIN indexes, and Row Level Security policies.

Enable Phone Auth provider. Configure MSG91 as SMS OTP provider (India-optimised). Test OTP delivery to a real +91 number before proceeding. Generate TypeScript types via `supabase gen types typescript` into `mobile/types/supabase.ts`.

## Acceptance Criteria

- All 7 tables exist with correct columns, types, and constraints
- All 3 ENUMs created with full value set from the architecture doc
- RLS enabled on every table; policy `user_owns_*` ensures `auth.uid() = user_id`
- GIN index on `wardrobe_items.occasion_tags` functional
- `cost_per_wear` computed column correctly calculates `purchase_price / wear_count`
- Phone Auth enabled; OTP to +91 test number delivers within 10 seconds
- Auto-generated TypeScript types match schema; import resolves in mobile workspace
- Supabase types generated via `supabase gen types typescript`

## Technical Notes

- MSG91 requires DLT registration for transactional SMS in India — takes 1-3 business days; start early
- RLS policies must use `auth.uid()` for Supabase to optimise query planning
- Migration must be idempotent (use `IF NOT EXISTS`)

## Edge Cases & Failure Modes

- MSG91 DLT registration rejection: have Twilio as fallback SMS provider configured but not activated
- Supabase service role key must NEVER be used in client code — only in backend/edge functions
