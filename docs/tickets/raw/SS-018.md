## Description

1. Verify Upstash Redis REST API's actual command shape for an atomic increment-with-expiry pattern (the current code does two separate calls — `INCR` then `EXPIRE` only on the first request in a window — which has a race: two concurrent first-requests could both see `count == 1` and both set `EXPIRE`, or neither request's `EXPIRE` fires before a crash between the two calls leaves the key with no TTL). Check whether Upstash's REST API supports a single atomic command (e.g. a pipelined request, or `SET`-with-`EX`-and-`INCR` equivalent) that avoids this two-call race, and use it if available.
2. Flip the fail-open behavior to fail-closed: when Upstash env vars are unset, or the REST call errors, `check_and_increment` should currently return `True` (allow) — change this so a real, costed AI adapter behind this rate limiter is never left unprotected by an infra outage. The zero-cost mock adapter it currently guards can keep fail-open behavior only if this is made configurable per-caller, not a blanket flip that would also affect any future real adapter using the same class.

## Acceptance Criteria

- Upstash REST command shape used in code is confirmed against Upstash's current published API docs (cite what was checked) — no longer flagged as unverified trained-knowledge in the module docstring
- The increment-then-conditionally-expire race (two concurrent first-requests both setting TTL, or a crash between the two calls leaving no TTL) is eliminated or explicitly justified as acceptable with reasoning, not left as an unexamined gap
- `check_and_increment` fails **closed** (denies the request) when Upstash env vars are unset or the REST call errors, unless the caller explicitly opts into fail-open (e.g. a constructor flag), so `MockStylingAdapter`'s current zero-risk usage can keep working unchanged while any future real adapter gets safe-by-default behavior
- Existing rate-limiter unit tests updated for the new default behavior; add a test covering the fail-closed path explicitly
- Module docstring updated to reflect verified (not trained-knowledge) status, dated
