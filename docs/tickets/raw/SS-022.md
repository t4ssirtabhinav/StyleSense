# SS-022 — Weather Integration (City-Based)

`[Feature]` `[P2]` `[Sprint 5]` `[1 pt]` Est: 3h
Depends on: SS-020

## Description

Supabase Edge Function calls the Open-Meteo API (free, no key needed) using the user's saved city. Returns `temp_c`, `condition`, `humidity`. Cached per city per hour. Outfit suggestion prompt (SS-020) enriched with weather context. "Dressing for 28°C, partly cloudy" shown on the suggestion screen.

## Acceptance Criteria

- Weather fetched automatically for the user's saved city
- Outfit AI receives weather data in its prompt
- Heavy rain → no white or silk suggestions
- Weather shown as a chip on the outfit suggestion screen

## Technical Notes

- Open-Meteo requires no API key/account provisioning — lowest-blocker external integration in this backlog so far
- Per-city-per-hour cache — reuse the existing Redis (Upstash) infra, not a new caching layer

## Edge Cases & Failure Modes

- User has no saved city (skipped onboarding Step 1, or it was optional) — suggestion flow must degrade gracefully, not block on missing weather
- Open-Meteo unavailable — suggestion generation should proceed without weather context rather than fail the whole request
