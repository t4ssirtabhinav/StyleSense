# SS-011 — Background Removal Pipeline (Replicate BRIA-RMBG)

`[Feature]` `[P0]` `[Sprint 3]` `[2 pts]` Est: 5h
Depends on: SS-010

## Description

Background removal for the premium wardrobe grid look. Replicate BRIA-RMBG model at $0.0023/run. FastAPI: `POST /wardrobe/remove-bg`. Validates JWT, checks the daily rate limit (Upstash Redis: `bg_remove:{user_id}:{date}`, 20/day free, unlimited premium). Calls Replicate, uploads `clean.png` to R2, updates `wardrobe_items.image_clean_url`. Also generates a 300px thumbnail.

Circuit breaker pattern: if 3 consecutive Replicate calls fail, open the circuit for 60 seconds, return a graceful fallback (original image, flagged `bg_pending`).

## Acceptance Criteria

- Clothing image returns a BG-removed PNG within 10 seconds
- Clean image stored in R2; URL saved to `wardrobe_items.image_clean_url`
- Free users limited to 20 BG removals/day; premium unlimited
- If Replicate fails: item saved with the original image, flagged `bg_pending` for retry
- Circuit breaker opens after 3 consecutive failures; auto-closes after 60s
- Each Replicate call logged: `user_id`, cost ($0.0023), `latency_ms`
- 300px thumbnail generated and stored at `/thumbnail.jpg`
- Processing time under 4s on average

## Technical Notes

- Replicate model: `bria-rmbg` via the `replicate` Python SDK
- Rate limit: Upstash Redis `INCR` with `EXPIRE` (1 day TTL) for an atomic counter
- Thumbnail: Pillow, 300px width, to reduce grid load time
- Process async: return immediately, notify via Supabase Realtime when done
- Rate limit counter resets at IST midnight, not UTC

## Edge Cases & Failure Modes

- Non-clothing image (screenshot): poor results — add a confidence check, warn the user
- Replicate cold start: first call after idle 30+ seconds; show a patience message
- Image with a transparent/white background already: detect and skip to save cost
- Batch upload of 10: queue sequentially to stay within Replicate rate limits
