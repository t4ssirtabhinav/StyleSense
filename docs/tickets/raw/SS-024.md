# SS-024 — Footwear Module (Separate Catalogue + Matching)

`[Feature]` `[P2]` `[Sprint 5]` `[2 pts]` Est: 6h
Depends on: SS-014, SS-020

## Description

Footwear tab within the wardrobe. Same upload/tag flow as regular items but a footwear-specific Gemini prompt (type: heels/flats/sneakers/jutis/kolhapuri/sandals/loafers; formality; colour). Outfit suggestion endpoint (SS-020) extended to always include a footwear pairing. "Best footwear for this outfit" section in outfit cards.

## Acceptance Criteria

- Footwear items display in a separate tab in the wardrobe
- AI suggests footwear alongside every outfit
- Footwear is tagged with a formality level (formal/ethnic/casual/sports)
- "Missing footwear" alert if no appropriate footwear exists for the occasion

## Technical Notes

- Reuses SS-010/SS-011/SS-012/SS-013's existing upload → BG-removal → tagging pipeline — this is a new *category* and *prompt variant*, not new infrastructure. Resist rebuilding the pipeline; extend the existing Gemini prompt/taxonomy path.
- Footwear `type`/`formality` face the same free-text-no-enum gap as `pattern`/`fabric` (`BL-064`) — decide explicitly whether footwear type gets a real DB enum (jutis/kolhapuri are India-specific values worth getting right) or joins the same deferred-taxonomy posture, rather than silently picking one.

## Edge Cases & Failure Modes

- User has clothing items but zero footwear — "missing footwear" alert (this ticket's own AC) rather than a broken/empty suggestion slot
- Footwear formality doesn't match the outfit's occasion (e.g. only sneakers owned, occasion is `wedding_guest`) — surface this as a gap/nudge, not a forced mismatched suggestion
